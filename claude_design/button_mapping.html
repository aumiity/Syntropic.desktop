MUI → ปุ่มของเรา : แผนที่โยงสี

พาเลต Material UI มาตรฐาน (น้ำเงิน/ม่วง/ส้ม) โยงเข้ากับระบบปุ่ม semantic token ของ Syntropic (teal + yellow). สรุปว่าสีไหนแทน role ไหน และ MUI แต่ละ stage ตกลงที่กลไกใดของปุ่มเรา.

1

โครงสร้าง “stage” ต่างกันคนละแบบ

MUI แยก 5 state มีสีของตัวเองทุกอัน. แต่ปุ่มเราใช้ token สำหรับ rest/hover, ส่วน pressed/disabled เป็น เอฟเฟกต์ ไม่ใช่สี.

MUI stageMUI ทำอะไรปุ่มเราทำอะไรกลไก
Enabledพื้น = .mainbg-<role>token --<role>
Hoveredพื้นเข้มขึ้น = .darkhover:bg-<role>-hovertoken L −7%
Pressed.dark + rippleย่อ + ขยับลง (ไม่เปลี่ยนสี)transform scale-95
Focused.main + วงแหวนเงาวงแหวน focustoken --ring
Disabledสลับเป็นเทา #E0E0E0จางลง 50% สีเดิมopacity 0.5
◆
ค่า MUI .dark (hover) ≈ token --<role>-hover ของเราพอดี → ยกมาใช้ได้ตรง ๆ. แต่ MUI Pressed-สี กับ Disabled-เทา ไม่มีที่ลงในปุ่มเรา (เราใช้ transform / opacity). อยากได้ต้องเพิ่มกลไกใหม่.
2

โยงสี : MUI Color → token ของเรา

แต่ละการ์ด: ซ้าย = MUI (main + hover) → ขวา = token เรา พร้อมปุ่มจริงเทียบข้างกัน.

4

ช่องว่าง 3 จุด (ถ้าอยากได้ MUI ครบ)

สิ่งที่ MUI มี แต่ปุ่มเรายังไม่มี, ต้องเพิ่มถ้าต้องการ.

1Text-button สีตาม role

ตอนนี้มีแค่ ghost (เทา) กับ link (teal). ไม่มีปุ่ม “info/success แบบไม่มีพื้น”. ใกล้สุด = *-soft (แต่มีพื้นจาง).

2Pressed เป็นสีเข้ม

เราใช้ scale/translate. อยากได้แบบ MUI ต้องเพิ่ม active:bg-<role>-hover.

3Disabled เป็นเทา

เราใช้ opacity-50 (จางสีเดิม). อยากได้เทาแบบ MUI ต้องทำ token/variant แยก.

⚠
จุดต้องตัดสินใจ : Primary MUI Primary เป็นน้ำเงิน แต่ Primary แบรนด์เราเป็นเขียว teal #0F5D56. หนูแนะนำโยงตามบทบาท (MUI-Primary → default teal) เพื่อรักษาแบรนด์ teal+yellow ไว้, ไม่ใช่โยงตามเฉดสีน้ำเงินที่จะทำให้ทั้งแอปกลายเป็นน้ำเงินแบบ MUI.
