02 กฎห้ามแตะ HARD

แต่ละข้อมี “เหตุการณ์พัง” อยู่เบื้องหลัง — ห้ามฝ่าฝืน

  • หน้า /theme คือแหล่งความจริง — ก่อนเพิ่ม/แก้ UI ให้เปิดดูแล้วหาแพตเทิร์นที่ตรง ลอกมา ห้ามคิดลายใหม่เอง
  • ใช้ semantic token เท่านั้น ห้ามใส่สีดิบของ Tailwind — ห้าม bg-blue-500, text-slate-600 ฯลฯ ใช้ bg-primary, text-foreground, bg-success-soft ขาด token ไหนให้เพิ่มใน :root+.dark ที่ index.css แล้วลงทะเบียนใน tailwind.config.js
  • ห้ามเขียน HTML element ดิบ — ใช้ src/components/ui/ เสมอ (<Button>, <Input>, <Switch>, <Dialog>…) ขาด variant ให้เพิ่มในไฟล์คอมโพเนนต์ ห้ามเลี่ยงด้วย element ดิบ
  • ห้ามสร้าง helper component ในโฟลเดอร์ src/pages/ — ถ้าใช้ซ้ำได้ ให้ย้ายไป src/components/ui/ (มีให้แล้ว: SectionCard, FormField, NativeSelect, Toggle)
  • Input เป็น ELEVATED โดยดีฟอลต์ — <Input> เปล่าๆ ถูกต้องอยู่แล้ว ไม่ต้องเติม variant="elevated" อีก (ดูข้อ 07)
  • ไอคอนใน <Button> ใช้ size-N ห้าม h-N w-N — มีกฎ :not([class*='size-']) บังคับไอคอนที่ไม่มี size- ให้เป็น 16px เงียบๆ ใช้กับค่า arbitrary ด้วย (size-[22px])
  • Tailwind v3 — CSS var ต้องใช้วงเล็บเหลี่ยม — w-[var(--x)] ถูก / w-(--x) ผิด (ไวยากรณ์ v4 ถูกทิ้งเงียบๆ ไม่มี error)
  • ลำดับขนาดตัวอักษรตามบทบาท — หัวข้อ ≥ text-base / เนื้อหา-ตาราง-label-ปุ่ม = text-sm / helper-caption-badge = text-xs เล็กกว่า text-xs ห้าม
  • ห้าม emoji ในของที่ส่งถึงผู้ใช้ — source / UI string / runtime text ใช้ไอคอน lucide + Badge variant + token สีแทน
  • Scrollbar บาง 6px ทั้งแอป ขนาดเดียว — ห้ามกำหนดความกว้างอื่นที่ใดก็ตาม
  • ใช้สีให้ครบจาน อย่าใช้แต่ primary/secondary/destructive — เลือกตามบทบาท: accent (เหลือง), primary-soft, info-soft, warm, success, outline, ghost, destructive2 และตระกูล *-outline ที่มีครบทุกสี (ไม่มี tertiary/brand-soft แล้ว — เปลี่ยนเป็น accent/primary-soft)
  • ภาษาไทยทั้งระบบ — ข้อความที่เห็นทั้งหมดเป็นไทย ระวัง line-height สคริปต์ไทย (วรรณยุกต์ซ้อนจะถูกตัดถ้า line-height แน่นไป)

04 ปุ่ม & Badge variant

เลือก variant ตาม “บทบาท” ของปุ่ม ไม่ใช่ “อันไหนดูกลางๆ สุด” — แอปควรดูมีสีสันหลากหลาย

ปุ่ม <Button> (button.tsx)

default · CTA หลัก/บันทึก secondary · ยกเลิก accent · เน้นด้วยเหลือง (เดิม tertiary) primary-soft · เน้นแบรนด์อ่อน (เดิม brand-soft) info-soft · เช่น “ปรับสต็อก” warm · รองโทนอุ่น outline · ปุ่มไอคอนกลางๆ / “แก้ไข” ghost · รองสุด destructive · ลบ/ยกเลิกบิล destructive2 · รองข้างปุ่มลบ success · ยืนยันเชิงบวก elevated · รองข้างปุ่มหลัก (ไม่ใช้เดี่ยว) link · ข้อความล้วน
การเปลี่ยนชื่อ (อย่าใช้ชื่อเก่า) tertiary → accent · brand-soft → primary-soft · ออร์ดินัลเก่า quaternary/quinary/senary → primary-soft/info-soft/warm (ค่าสีเท่าเดิม) · ยังมีตระกูล *-outline ครบทุกสี + neutral/muted-outline และ elevated/elevated-destructive/elevated-warning

Badge <Badge> (badge.tsx)

ชื่อเดียวกับปุ่ม บวกเพิ่ม warning (สถานะ) และ danger (แดงทึบ) — เฉพาะ Badge ใช้กับแท็ก สถานะ ป้าย อย. (เช่น ข.ย.13) เครื่องหมายระดับ

คำแนะนำเวลาทำ UI ใหม่

  • แยกปุ่มด้วยสีตามงาน: แก้ไข=outline, ข้อมูล/รายละเอียด=warm, เปิดลิงก์นอก=primary-soft, ปรับสต็อก=info-soft, ลบ=destructive, บันทึกหลัก=default
  • ชิป/badge ตกแต่ง: หยิบ accent/primary-soft/info-soft/warm ก่อนจะตกไปใช้ secondary หรือเทา
  • พื้นหลังอ่อนของ section: bg-primary-soft, bg-info-soft, bg-warm (อย่าใช้ bg-muted กับทุกอย่าง)
  • ขาด role? เพิ่ม variant ใน buttonVariants/badgeVariants + token ใน :root+.dark — ห้าม hardcode hex

05 ตัวอักษร & ฟอนต์

ลำดับฟอนต์: var(--font-latin), var(--font-thai), sans-serif — สลับได้จากหน้า /theme

ดีฟอลต์ตามธีม

  • สว่าง: Latin = Inter / ไทย = IBM Plex Sans Thai
  • มืด: Latin = Google Sans / ไทย = Sarabun
  • เอกสารพิมพ์ ใช้ Sarabun เป็นค่าเริ่ม (ฟอร์ม ข.ย. ทางการ)

ฟอนต์ไทยสำรองที่มากับแอป

  • IBM Plex Sans Thai (Looped), Sarabun, SF Thonburi, Bai Jamjuree, Anuphan, Noto Sans Thai (+ Looped)
  • ฟอนต์ไทยถูกจำกัด unicode-range ที่ U+0E00–0E7F → ข้อความที่เป็นตัวเลขล้วนจะเรนเดอร์ด้วยฟอนต์ Latin

ขนาด

  • html { font-size:16px } (ฐาน UI ที่เห็นจริง ~15px) · ห้ามใช้ tabular-nums (มติโปรเจกต์ — เลิกใช้กับโค้ดใหม่)
  • ลำดับชั้น: หัวข้อ ≥ text-base · เนื้อหา/ตาราง/label/ปุ่ม = text-sm · helper/caption/badge = text-xs · เล็กกว่านี้ห้าม

06 มุมโค้ง & เงา

  • --radius-card = 1rem → rounded-card — มุมของการ์ด/แผงลอยทุกอัน (แหล่งเดียว)
  • --radius-control / --radius = 0.5rem → rounded-control / rounded-lg — ปุ่ม/ช่องกรอก/แผง select/popover
  • ห้ามใช้ rounded-xl/rounded-2xl ดิบๆ — ใช้ token
  • --shadow-card → shadow-card · ปุ่ม/ช่องกรอกใช้ shadow-sm เป็นส่วนหนึ่งของลุค elevated

07 ELEVATED — พื้นผิวหลักของระบบ HARD

ลุคประจำบ้านของ control/แผง คือ “ยกลอย”: bg-card + border border-border + shadow-sm เหมือนการ์ดยกตัวลอยเหนือพื้นหลัง

  • เป็นดีฟอลต์ของ Input แล้ว — Input/Textarea/SelectTrigger ที่ไม่ใส่ variant จะ elevated เอง → เลิกเติม variant="elevated" ด้วยมือ (เป็น alias ที่เหมือนดีฟอลต์)
  • ลุคแบนเก่า (bg-input/bg-muted) เป็นของเสริม เปิดด้วย variant="filled" เฉพาะที่ตั้งใจอยากได้ช่องจมเข้าไป
  • ข้อยกเว้น — Button ดีฟอลต์ของปุ่มคือ CTA teal หลัก ต้องคงไว้ ห้ามสลับเป็น elevated
  • อ้างอิงของจริง: src/pages/Products/EditProduct/GeneralTab.tsx
ปุ่ม footer ใน Dialog ตามบทบาท ปุ่มเดี่ยว = บทบาทหลัก → default (กลาง/บวก: ปิด/ตกลง/บันทึก) หรือ destructive (ลบ) · สองปุ่ม = หลัก + รอง elevated (ยกเลิก/กลับ) · elevated ห้ามเป็นปุ่มเดี่ยว · destructive2 = ปุ่มรองข้างปุ่มลบ

08 เลย์เอาต์ Table-Card HARD

มาตรฐานของหน้ารายการ (Products, EditProduct, Manage…) กรอบนอก: bg-card rounded-card shadow-card overflow-hidden

4 โซนพื้นหลัง — สีคือสิ่งที่แยกโซน

1 · แถบหัวข้อบน (ชื่อ/จำนวน + ปุ่มเพิ่ม)
bg-card ขาว · ไม่มีเส้นขอบ — แถบ muted ข้างล่างทำหน้าที่แบ่งเอง
2 · แถวหัวคอลัมน์ (thead)
bg-muted · เป็นแถบ muted แถบเดียวในการ์ด · sticky
3 · แถวข้อมูล (tbody)
bg-card ขาว
4 · แถบสถานะ/ยอดรวมล่าง
bg-card + border-t border-border · เป็นแถบเดียวที่มีเส้นขอบ (บน) · h-12
จำง่ายๆ มีแค่แถบหัวคอลัมน์ที่เป็น muted · แถบล่างได้เส้นขอบบน · แถบหัวบนไม่มีเส้นขอบ

ไอคอนนำหน้าหัวการ์ด HARD

<TintIcon> ของหัว table-card เป็น tint="neutral" + bordered เสมอ (ลุคยกลอย ไม่มีสี) — ห้ามใส่สี tint สีตามบทบาทสงวนไว้ให้หัว SectionCard เท่านั้น

ความกว้างคอลัมน์ HARD

ชนิดตารางวิธี
ตาราง แสดงผล/รายการทุก <TableHead> ใส่ min-w-XX และ ไม่ใส่ table-fixed — คอลัมน์ยืดหดได้แต่ไม่ยุบต่ำกว่าขั้นต่ำ
กริด กรอกข้อมูลแบบสเปรดชีต (ช่องแก้ไขได้ + เดินด้วยคีย์บอร์ด)table-fixed + w-[N%] (เปอร์เซ็นต์ ยังตอบสนองได้) · คุมขนาด <Input> ข้างในด้วย min-w-/max-w- · อ้างอิง: Purchase/index.tsx

ปุ่ม action ในแถว HARD

  • ใช้ <Button size="icon-lg" variant="elevated"> ทรงสี่เหลี่ยมจัตุรัส ไอคอน lucide อันเดียว ไม่ override ความกว้าง · ใส่ title เสมอ · ห้าม ใส่สี tint ตามบทบาท
  • มาตรฐาน: ปุ่ม MoreHorizontal (“ตัวเลือก”) เปิด <Popover> เมนู — รายการเมนูเป็น <button> ธรรมดา รายการลบใช้ text-destructive hover:bg-destructive/10
  • มีแอ็กชันเดียว: ข้ามเมนู ใช้ปุ่มไอคอน elevated ตรงๆ (เช่น Eye ดูรายละเอียด)

หัวตาราง sticky + อื่นๆ

  • sticky: ใส่ sticky top-0 z-10 bg-muted ที่ <th> (ไม่ใช่ <thead>) + เส้นบางที่เลื่อนตามด้วย shadow-[0_1px_0_var(--border)]
  • hover แถว: hover:bg-primary-soft/60 transition-colors
  • สถานะว่าง: ไอคอน lucide size-10 opacity-30 + ข้อความไทย + py-16

09 แถบกรอง & ระยะห่าง HARD

แยกให้ออกระหว่าง 2 แถบที่ความสูงต่างกัน

แถบความสูงแถบcontrol ข้างใน
แถบกรอง/topbar (search + ตัวกรอง)h-14 px-2ทุกตัว h-10 (Input/SelectTrigger/Button ต้องใส่เอง · DateInput/DateRangePicker/Combobox มีมาแล้ว — ห้าม override เป็น h-9 จะทำปุ่มปฏิทินเพี้ยน)
แถบหัวบน / footer-paginationh-12ปุ่ม h-9 (Button size="lg")
อย่าปนกัน ห้ามเอา control h-9 ไปใส่ในแถบ h-14 — ทำให้ไม่ตรงแนวกับ DateRangePicker (เป็นแพตเทิร์นเก่าที่เลิกแล้ว)

พื้นที่ตารางมีขอบข้าง border-l-8 border-r-8 border-card (สีเท่าพื้นการ์ด = เว้นระยะ 8px โดยไม่ใช้ padding)

10 ตารางจัดลำดับ (ลากเรียง) HARD

สร้างบน framer-motion Reorder (มีอยู่แล้ว ห้ามเพิ่มไลบรารี DnD) · src/components/ui/sortable.tsx

  • ต้องเปิดโหมดก่อนถึงจะลากได้ — ห้ามปล่อยให้ลากได้ตลอด หัวแถบมีปุ่ม “จัดลำดับ” (variant="info-soft", ปิดเมื่อมีน้อยกว่า 2 แถว)
  • ร่างเก็บในเครื่อง, ยืนยัน/ยกเลิกชัดเจน — อย่าบันทึกทุกครั้งที่ปล่อย (onDragEnd) เข้าโหมดแล้ว snapshot ลำดับเดิมไว้ · “ยกเลิก” (destructive2) คืนค่าเดิมไม่ยิง IPC · “เสร็จสิ้น” (success) บันทึกแล้วโหลดใหม่
  • backend เป็นคนเลขลำดับใหม่ — IPC รับ array id ที่เรียงแล้ว เขียน sort_order = 1..n ใน transaction เดียว
  • ใช้ได้เฉพาะตารางที่มีคอลัมน์ sort_order — product_categories มี / drug_types ไม่มี (ต้อง migrate schema ก่อน)

11 Dialog / Modal HARD

สัญญาการโต้ตอบ (ทุก modal ไม่มีข้อยกเว้น)

  • คลิกข้างนอกไม่ปิด — บังคับใน dialog.tsx แล้ว ห้าม bypass
  • Esc ปิด (ดีฟอลต์ Radix — เปิดไว้)
  • Enter = สั่งปุ่มหลัก OK — ต่อ Enter ที่ช่องกรอกหลักหรือผ่าน onKeyDown เรียก handler เดียวกับปุ่ม OK

โครงสร้างบังคับ

ทุก <DialogContent> ต้องมี <DialogHeader> + <DialogTitle> + <DialogBody> + <DialogFooter>

  • DialogTitle = text-xl · ปุ่ม footer มัก size="xl" · Switch ใน modal = size="lg"
  • Dialog ยืนยัน/ลบ ใช้การ์ดข้อมูลแบบมีโครง (rounded-xl border bg-card shadow-sm + แถว label/value + กล่องเตือน tinted-soft) ใน slot content — ไม่ใช่ข้อความยาวๆ ใน description · อ้างอิง: NegativeStock.tsx / Expenses.tsx

12 กฎหน้า POS HARD

การค้นหา

  • ช่องค้นหาโฟกัสตลอด — มี global click listener ดึงโฟกัสกลับเมื่อคลิกพื้นที่ที่ไม่ใช่ปุ่ม · เคารพ dialog ที่เปิดอยู่
  • Modal ขนาดคงที่ 600×480 · header/หัวคอลัมน์/footer = shrink-0 · ลิสต์ผลลัพธ์ = flex-1 overflow-y-auto · ที่ว่างคงว่าง ไม่ reflow
  • ไฮไลต์เป็นของคีย์บอร์ดเท่านั้น — highlightIdx รีเซ็ตเฉพาะตอน query เปลี่ยน · ห้ามใส่ onMouseEnter ที่แถว (scrollIntoView ทำให้เมาส์ลั่นแล้วรีเซ็ตไฮไลต์) · hover ใช้ CSS อย่างเดียว
  • ลูกศรขึ้น/ลง เรียก e.preventDefault() กันพฤติกรรมดีฟอลต์

การเลือกหน่วย — หน่วยหลักอยู่บนสุดเสมอ

  • หน่วยฐาน (“หลัก”) ต้องเป็นตัวเลือกแรกทั้งใน cart unit dialog และ search modal · สถานะการเลือกห้ามมีผลต่อลำดับ
  • สังเคราะห์หน่วยฐานจาก product.unit_name เท่านั้น — ห้าม fallback ไป item.unit_name (นั่นคือหน่วยที่เลือกอยู่ จะทำให้ติดป้าย “หลัก” ผิดตัว)
  • หน่วยฐานอยู่ที่ products.unit_id · product_units เก็บเฉพาะหน่วยที่ไม่ใช่ฐาน · POS สังเคราะห์แถวฐาน id: -1 · search modal ส่ง {product, unit: null} เป็นตัวแรก

13 การเคลื่อนไหว / แอนิเมชัน

แอนิเมชันใช้ได้ — ไม่ห้าม ถ้ามันทำให้ UI สวยขึ้นและเหมาะสม สนับสนุนให้ใส่ · เพิ่มไลบรารี motion ใหม่ก็ได้เมื่อเหมาะ — ขอแค่บอกแผนกับผู้ใช้ก่อนลงมือจริง แล้วได้ OK ก่อน
  • ที่มีอยู่แล้ว: framer-motion (pill ของ Tabs เลื่อน) และ tailwindcss-animate — หยิบใช้ได้เลย
  • จะเพิ่ม gsap/lenis/anime.js ฯลฯ ได้ตามความเหมาะสม/ความสวย — แค่แจ้งก่อน (และอย่ารัน npm install เปล่าๆ ใช้ --ignore-scripts ไม่งั้น better-sqlite3 พัง)
  • ยังคงทำทางเลือกสำหรับ prefers-reduced-motion: reduce เพื่อ accessibility

14 หมายเหตุสำหรับ skill impeccable

ส่วนนี้คือสะพานเชื่อม “playbook ทั่วไปของ skill ภายนอก” กับ “โค้ดเบสนี้” — เมื่อกฎทั่วไปขัดกับ House Invariant ให้ House Invariant ชนะ

  • “การ์ดคือคำตอบขี้เกียจ / การ์ดซ้อนการ์ดผิดเสมอ” → ใช้ไม่ได้ที่นี่ นี่คือเครื่องมือ operator ข้อมูลหนาแน่น · table-card 4 โซน + SectionCard/MetricCard/StatCard เป็นแพตเทิร์นตั้งใจ · POS ใช้การ์ดมีขอบโดยจงใจ — อย่าไปรื้อ
  • จานสี → จานปัจจุบันเป็น token HSL ใน src/index.css และเป็นค่าตั้งต้น (รักษาอัตลักษณ์เดิมเป็นปกติ อย่าสลับสีแบรนด์เงียบๆ) · แต่เสนอจานสีใหม่ได้ ถ้ามีความจำเป็นจริงและสวย/เหมาะกว่า — เสนอผู้ใช้ก่อนแล้วได้ตกลงค่อยทำ · ยังต้องอ้าง token เสมอ (เพิ่ม token ใหม่ใน :root+.dark) ห้าม hardcode สีดิบของ Tailwind
  • สอดคล้องอยู่แล้ว: การห้าม side-stripe border, gradient text, glassmorphism ตกแต่ง, เทมเพลต hero-metric, eyebrow ตัวพิมพ์ใหญ่, em dash, คำตลาด — ตรงกับโปรเจกต์นี้ บังคับต่อไปได้
