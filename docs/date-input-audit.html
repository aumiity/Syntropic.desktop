2. DateInput — ตัวเดียวที่มี logic ตรวจเช็ค (เพราะพิมพ์ได้)

พิมพ์ตัวเลขแล้ว auto-format เป็น DD/MM/YYYY เก็บลง state เป็น ISO YYYY-MM-DD (ค.ศ., ไม่ใช่ พ.ศ.)

พฤติกรรมการพิมพ์

  • autoFormat() — รับเฉพาะตัวเลข ตัดเหลือ 8 หลัก ใส่ / ให้เอง: 25 → 25/06 → 25/06/2026
  • displayToIso() — แปลง DD/MM/YYYY → YYYY-MM-DD พร้อม ตรวจว่าวันมีจริง

กฎตรวจ "วันมีจริง" (displayToIso)

  • เดือนต้อง 1–12
  • ปีต้อง 1900–9999 (เผื่อ 9999 = สินค้าไม่มีวันหมดอายุ)
  • วันต้องไม่เกินวันสุดท้ายของเดือน new Date(yy, mm, 0).getDate() — รองรับ leap year
  • ผิดข้อใดข้อหนึ่ง → คืน ''

หัวใจ: logic การ commit ค่าออก parent

// ทุกครั้งที่พิมพ์
const iso = displayToIso(formatted)
onChange(iso || '')

วัน valid       → onChange(iso)
ทุกกรณีอื่น     → onChange('')   // พิมพ์ค้าง / 99/99/9999 / ว่าง

ทำไมสำคัญ — invariant

ค่ามั่วจะไม่มีวันไหลลง DB เลย — parent เห็น '' เสมอเมื่อไม่ใช่วันจริง. เดิม commit '' เฉพาะตอนช่องว่าง ทำให้เลขมั่วทิ้ง parent ไว้ที่ค่าเก่า (ที่ valid) แล้ว submit ผ่านแบบเงียบ ๆ. (codified กฎ #12 ใน ui-theming.md)

logic การโชว์ขอบแดง

rawInvalid = text.length > 0 && !displayToIso(text)
invalid    = rawInvalid && (!focused || text.length === 10)
  • กำลังพิมพ์ ยังไม่ครบ 10 ตัว → ยังไม่แดง (กันกระพริบ)
  • ครบ 10 ตัวแต่ไม่ใช่วันจริง เช่น 99/99/9999 → แดงทันที แม้ยัง focus
  • blur ออกทั้งที่พิมพ์ตก → แดง (กันเคส exp หายเงียบ)
  • ใช้ aria-invalid → กรอบแดงอย่างเดียว ไม่มี ring ซ้อน และ ไม่มีข้อความใต้ช่อง
  • เลือกจากปุ่มปฏิทิน → commit ISO ที่ valid เสมอ (ข้าม validation ได้)

required เป็นหน้าที่ของ parent ไม่ใช่ของ DateInput

DateInput ไม่รู้จัก required — มันแค่การันตีว่า "ถ้าไม่ใช่วันจริงคือ ''". การบังคับกรอกต้องเช็ค !value ที่ parient เอง:

  • ExpenseFormDialog.tsx:81 → if (!form.expense_date) toast('กรุณาระบุวันที่')
  • AddProductWizard.tsx:409 → gate ปุ่ม Next ด้วย row.expiry_date !== ''

DateRangePicker / PeriodPicker — ใช้แค่ใน /theme (showcase) แล้ว. ของจริงย้ายไป MultiDatePicker หมด.

logic ของ range/period — ไม่มี validation

พิมพ์ไม่ได้ → ทุกค่ามาจากปฏิทิน/preset = valid เสมอ หรือ '' ตอนล้าง. สิ่งที่มีคือ:

  • โหมด day/month/year/custom — เปลี่ยนโหมดจะ "zoom" จาก anchor เดิม (rangeForMode / rangeForMultiMode)
  • stepper ◀ ▶ — เลื่อนทีละ 1 หน่วยตามโหมด; custom เลื่อนเท่าความยาวช่วงตัวเอง
  • โชว์ปี พ.ศ. ในตัว picker (year + 543) แต่ค่าที่เก็บเป็น ค.ศ. ISO ตามกฎ
  • empty from/to → stepper fallback เป็น dayjs() วันนี้ กัน Invalid Date

5. สรุปสั้น

  • DateInput = ตัวเดียวที่มี logic ตรวจเช็คจริง (วันมีจริง + ขอบแดง + commit '' เมื่อมั่ว)
  • required ปล่อยให้ parent เช็ค !value เอง
  • range/period picker = ปฏิทินล้วน valid-by-construction ไม่ต้อง validate
  • ทุกตัวเก็บ ISO YYYY-MM-DD (ค.ศ.) แสดงผล DD/MM/YYYY ผ่าน formatDate()
