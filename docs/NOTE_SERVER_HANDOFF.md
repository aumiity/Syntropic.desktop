# Handoff: ติดตั้ง "Task Board (บันทึกงาน)" ลงเว็บเซิร์ฟเวอร์ที่บ้าน

> เอกสารนี้คือ **prompt สำหรับ Claude ที่รันอยู่บนเครื่องเซิร์ฟเวอร์** ให้ทำงานต่อ
> ผู้สั่งงานเตรียมมาจากโปรเจกต์อื่น (เครื่องเดสก์ท็อป) — Claude บนเซิร์ฟเวอร์ **ไม่จำเป็นต้องรู้จักโปรเจกต์ต้นทาง** ทุกอย่างที่ต้องใช้อยู่ในเอกสารนี้ + ไฟล์ที่แนบมา

## 0. TL;DR

มี **เว็บค้นหาสินค้า** รันอยู่บนเครื่องนี้แล้ว ออนไลน์ 24/7 เข้าผ่าน Tailscale ที่ `http://100.94.208.11:8088`

ภารกิจ: **เพิ่มหน้า "บันทึกงาน" (task board / kanban)** เข้าไปในเว็บเดิมนั้น ที่ path `/note`
- Frontend สำเร็จรูปแล้ว = ไฟล์ **`NOTE.html`** (แนบมาด้วย) — เป็น HTML ไฟล์เดียวจบ vanilla JS/CSS ไม่ต้อง build
- งานของคุณคือ **ต่อ backend ให้มันเซฟข้อมูลฝั่งเซิร์ฟเวอร์** (ลงไฟล์ JSON หรือ DB) แทนที่กลไกเดิมที่เซฟเป็นไฟล์ในเครื่อง
- แล้ว **เพิ่มปุ่ม/ลิงก์จากหน้าค้นหาสินค้า → `/note`**

เพราะเซิร์ฟเวอร์ออนไลน์ตลอด → **เซิร์ฟเวอร์คือแหล่งข้อมูลจริง (single source of truth) ไม่ต้องใช้ git/sync ใดๆ** เปิดจากเครื่องไหน/มือถือผ่าน Tailscale ก็เห็นข้อมูลชุดเดียวกัน

## 1. ไฟล์ที่แนบมากับ prompt นี้

| ไฟล์ | คืออะไร |
|------|---------|
| `NOTE.html` | **Frontend ตัวจริง** ของ task board — ใช้ตัวนี้เลย แก้แค่ส่วน "โหลด/เซฟข้อมูล" |
| `NOTE.data.js` | ไฟล์ข้อมูลตั้งต้น (รูปแบบเดิมของฝั่งเดสก์ท็อป) — ใช้เป็น seed ได้ มันคือ `window.NOTE_DATA = { updatedAt, work, done }` |

> ถ้าไม่ได้รับไฟล์ `NOTE.html` มาด้วย ให้ขอจากผู้ใช้ก่อน (อย่าสร้างใหม่จากศูนย์ถ้ายังไม่จำเป็น — สเปกหน้าตา/พฤติกรรมอยู่ใน §6). ข้อมูลตั้งต้นมีฝังไว้ใน §7 ของเอกสารนี้แล้ว ไม่ต้องพึ่ง `NOTE.data.js`

## 2. เป้าหมาย / Acceptance criteria

ถือว่าสำเร็จเมื่อ:
1. เปิด `http://100.94.208.11:8088/note` แล้วเห็น task board พร้อมข้อมูลตั้งต้น **41 งาน (เสร็จแล้ว 30 / กำลังทำ 11)**
2. ติ๊กงานเสร็จ / เพิ่ม / แก้ข้อความ / ลบ / จัดลำดับ → **กด reload แล้วข้อมูลยังอยู่** (เซฟฝั่งเซิร์ฟเวอร์จริง)
3. เปิดจากอีกเครื่อง/มือถือผ่าน Tailscale → เห็นข้อมูลชุดเดียวกัน
4. หน้าค้นหาสินค้าเดิม **มีปุ่ม/ลิงก์ไป `/note`** และยัง **ทำงานปกติทุกอย่าง ไม่พัง**

## 4. ขั้นที่ 2 — Backend: ที่เก็บข้อมูล + endpoints

### 4.1 ที่เก็บข้อมูล
เก็บเป็นไฟล์ **`note-data.json`** (วางข้างแอป ที่ path ที่เขียนได้) รูปแบบ:
```json
{ "updatedAt": 1781872230981, "work": [ {"id":"w1","text":"..."} ], "done": [ {"id":"d1","text":"..."} ] }
```
- `work` = งานที่ยังไม่เสร็จ, `done` = งานที่เสร็จแล้ว, ลำดับใน array = ลำดับแสดงผล
- `updatedAt` = epoch ms ของการแก้ล่าสุด
- ครั้งแรกที่ยังไม่มีไฟล์ → seed จากข้อมูลใน **§7**

(ถ้าจะใช้ DB ก็ได้ แค่ทำให้ endpoint ด้านล่าง read/write ได้เหมือนกัน)

### 4.2 Endpoints (prefix `/note`)
| Method | Path | หน้าที่ |
|--------|------|---------|
| `GET`  | `/note` | เสิร์ฟไฟล์ `NOTE.html` |
| `GET`  | `/note/data` | คืน JSON `{updatedAt, work, done}` ปัจจุบัน (อ่านจาก store; ถ้ายังไม่มี → seed §7) |
| `POST` | `/note/save` | รับ body JSON `{updatedAt, work, done}` → เขียนทับ store แบบ atomic → ตอบ `{"ok":true}` |

ตัวอย่างสั้นๆ (เลือกตาม stack จริง):

**Node / Express**
```js
const fs = require('fs'); const path = require('path');
const STORE = path.join(__dirname, 'note-data.json');
app.get('/note', (req,res)=> res.sendFile(path.join(__dirname,'NOTE.html')));
app.get('/note/data', (req,res)=>{
  res.type('application/json').send(fs.existsSync(STORE) ? fs.readFileSync(STORE) : JSON.stringify(SEED));
});
app.post('/note/save', express.json({limit:'2mb'}), (req,res)=>{
  const {updatedAt,work,done} = req.body;
  fs.writeFileSync(STORE, JSON.stringify({updatedAt,work,done},null,2));
  res.json({ok:true});
});
```

**PHP (พื้นๆ)** — `note.php` (เสิร์ฟ HTML), `note_data.php` (GET คืน JSON), `note_save.php` (POST เขียนไฟล์ `file_put_contents`)

**Python / Flask**
```python
@app.get("/note")        # return send_file("NOTE.html")
@app.get("/note/data")   # return json ของ store หรือ SEED
@app.post("/note/save")  # json.dump(request.get_json(), open(STORE,"w"))
```

## 5. ขั้นที่ 3 — Frontend: แก้ `NOTE.html` ให้คุยกับเซิร์ฟเวอร์

`NOTE.html` ปัจจุบันออกแบบมาให้รันแบบไฟล์ในเครื่อง (เซฟ = ดาวน์โหลดไฟล์). ต้องเปลี่ยน **เฉพาะส่วนโหลด/เซฟ** ดังนี้ (ส่วน UI/ลาก/undo ฯลฯ ไม่ต้องแตะ):

1. **ตัดการโหลดแบบไฟล์ออก** — ลบบรรทัด
   ```html
   <script src="./NOTE.data.js"></script>
   ```
   (อยู่ก่อน `<script>` ตัวหลัก) เพราะจะโหลดผ่าน fetch แทน

2. **โหลดจากเซิร์ฟเวอร์ตอนเปิด** — ในสคริปต์หลัก ฟังก์ชัน `load()` อ่านจาก `window.NOTE_DATA`. ให้เปลี่ยนเป็น: `fetch('/note/data')` มาก่อน แล้วค่อย render. โครงสร้าง state คือ `{ work:[{id,text}], done:[{id,text}], updatedAt }` (เหมือน `/note/data`). เก็บ localStorage เป็น cache ออฟไลน์ได้ แต่ให้ **ถือข้อมูลเซิร์ฟเวอร์เป็นหลัก**

3. **เซฟกลับเซิร์ฟเวอร์ — แนะนำ "auto-save"** (เพราะเซิร์ฟเวอร์ออนไลน์ตลอด ไม่ต้องมีปุ่มเซฟให้ลืมกด):
   - ในโค้ดมีฟังก์ชัน `markChanged()` ที่ถูกเรียกทุกครั้งที่มีการแก้ข้อมูล → ให้ยิง `POST /note/save` แบบ **debounce ~400ms** ตามหลัง `markChanged()`
   - ปุ่มเดิม `id="export-md"` (ป้าย "ส่งออก NOTE.data.js") → เปลี่ยนเป็นตัวบอกสถานะ เช่น "บันทึกแล้ว ✓ / กำลังบันทึก…" หรือจะทำเป็นปุ่ม "บันทึก" กดเองก็ได้ (แต่ auto-save ลื่นกว่า)
   - ปุ่ม/ฟังก์ชัน import และ "คัดลอก Markdown" จะเก็บไว้หรือลบก็ได้ (บนเซิร์ฟเวอร์ไม่จำเป็นแล้ว)

```js
// ตัวอย่าง auto-save (debounced)
let saveTimer;
function pushToServer(){
  clearTimeout(saveTimer);
  saveTimer = setTimeout(()=>{
    fetch('/note/save', {method:'POST', headers:{'Content-Type':'application/json'},
      body: JSON.stringify({updatedAt: state.updatedAt, work: state.work, done: state.done})});
  }, 400);
}
// เรียก pushToServer() ทุกที่ที่เดิมเรียก markChanged()
```

> หมายเหตุ: path ทั้งหมดใช้ **absolute** (`/note/data`, `/note/save`) เพราะหน้าเสิร์ฟที่ `/note`

## 6. คุณสมบัติ UI ที่ "ห้ามทำหาย" (เผื่อต้องสร้างใหม่)

`NOTE.html` มีของพวกนี้อยู่แล้ว — ถ้าแก้ ระวังอย่าให้หาย; ถ้าต้องสร้างใหม่ ให้มีครบ:
- **2 คอลัมน์:** "เสร็จแล้ว" (ซ้าย) / "กำลังทำ" (ขวา) — จอแคบยุบเป็นคอลัมน์เดียว
- กด **วงกลมหน้างาน** = สลับสถานะ (ย้ายข้ามคอลัมน์ + เด้งบนสุด)
- **คลิกข้อความ** = แก้ inline ได้เลย (Enter/คลิกที่อื่น = บันทึก)
- **ลากจัดลำดับ** ภายในคอลัมน์ + ลากข้ามคอลัมน์
- ปุ่ม **ลบ** + **Undo toast** ("เลิกทำ") เด้งมาให้กดคืน (กันเผลอติ๊ก/เผลอลบ)
- **กระพริบไฮไลต์ + เลื่อนจอ** ไปหางานที่เพิ่งย้าย (หาเจอง่าย)
- แถบ **progress + นับจำนวน** เสร็จ/ทั้งหมด
- ปุ่มสลับ **โหมดมืด/สว่าง**
- **โทนสี:** ขาว–ม่วงอ่อน (lavender); **UI ภาษาไทยล้วน; ห้ามใช้ emoji ใน UI** (ใช้ไอคอน SVG ที่ฝังในไฟล์)
- ค้นหาในหน้าใช้ Ctrl+F ของเบราว์เซอร์

## 9. ข้อห้าม / ข้อควรระวัง

- **ห้ามทำเว็บค้นหาสินค้าเดิมพัง** — เพิ่มแบบแยกส่วน isolated, ทดสอบว่าของเดิมยังทำงาน
- ถ้ามี auth → เอา `/note` + `/note/data` + `/note/save` ไว้หลัง auth เดียวกัน (งานส่วนตัว)
- เขียนไฟล์ `note-data.json` แบบ atomic (เขียน temp แล้ว rename) กันไฟล์พังตอนเขียนพร้อมกัน
- **อย่าแปลงบอร์ดเป็น framework** — มันเป็น HTML ไฟล์เดียว vanilla ตั้งใจให้เรียบง่าย คงไว้แบบนั้น แก้แค่ load/save
- UI ภาษาไทย, ไม่มี emoji ใน UI
