## 🔴 2. Click-test ค้างสะสม

หลายฟีเจอร์ tsc ผ่าน + Priest PASS แต่ build pipeline (Hunter) รัน Electron ไม่ได้ → ค้างคิวทดสอบจริง

> เจ้าของ click-test ด้วยมือผ่านแล้วหลายส่วน (2026-06-06) แต่คิวต่อไปนี้ระบุไว้ใน `PROGRESS.md`:

**คิว User Login (สำคัญ — เกี่ยวกับ security):**
1. Session isolation — admin → ล็อกจอ → staff login → DevTools `financeSummary({})` ต้อง `FORBIDDEN`
2. Session อยู่รอดตอน navigate — สลับหน้า 5–6 ครั้ง → sensitive IPC ยังทำงาน
3. Manager-override — staff ยกเลิกบิล/แก้ราคา/ปรับสต็อก → dialog → รหัสแอดมินผ่าน, รหัสผิด reject
4. DeadStock — staff ไม่เห็นคอลัมน์ต้นทุน; DevTools `inactiveProducts({})` → `cost_value: null` ทุกตัว
5. Recovery — ลืมรหัส → recovery code → รหัสใหม่ → code ใหม่ออก → login
6. Fresh install — ลบ DB → wizard 4 steps → ตั้งรหัสแอดมิน → recovery code โชว์

**คิวอื่นที่ระบุ NOT click-tested:** Expenses, First-run Setup, Receipt/tax-invoice, Quotation (2 เฟส), Negative-stock, POS alerts, Bundle, ขย.9, h-10 sweep

## 🟠 3. ระบบ VAT (Phase 2 + 3 + Purchase-side)

🔗 memory: `project_vat_phasing`

- ✅ **Phase 1** (setup wizard ตัดสินใจ VAT ครั้งเดียว) เสร็จ 2026-05-31
- 🔴 **VAT-registered ถูกบล็อกที่ setup** (2026-06-06) — เลือก "จดทะเบียน VAT" ไม่ผ่าน (toast "ระบบยังไม่สามารถใช้งานได้") เพราะ subsystem ยังไม่พร้อม → ร้าน onboard เป็น VAT ไม่ได้ตอนนี้
  - re-enable = เอา field tax-id/branch/rate/date กลับ + ปลด early-return ใน `validateStep2` (มี comment ชี้ทางในไฟล์)
- ⬜ **Phase 2** — ซ่อน UI VAT ทั้งหมดเมื่อร้านเป็น NO-VAT mode
- ⬜ **Phase 3** — ล็อก/เอา toggle VAT ออกจาก Settings + flow "upgrade to VAT" ที่ปลอดภัย (audit log) กัน VAT ถูกปิดกลางคัน
- 🔴 **Purchase-side VAT (ภาษีซื้อ / ภ.พ.30)** — ยังไม่มีเลย! ตอนนี้มีแต่ output/sales VAT → ยังออก ภ.พ.30 (VAT payable = ขาย − ซื้อ) ไม่ได้
  - hook อนาคต: ตาราง `expenses` เป็นที่เก็บที่เหมาะ (เพิ่มคอลัมน์ `vat_amount`/`has_vat`)
- ❌ off-the-books / "ขายนอกระบบ" mode = **ปฏิเสธถาวร** (เลี่ยงภาษี — ห้ามสร้าง)
