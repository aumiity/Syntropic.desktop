==========================================================
CRITICAL ISSUES (need fixing)
==========================================================
1. Label save sends 4 non-existent columns: label_time_id, advice_id,
   show_barcode, is_default.
   - ADD label: silently lost (handler INSERT has an explicit column list).
   - EDIT label: SQL error "no such column" — UPDATE aborts, edit fails.
   Fix options: (a) add columns to schema.ts to match PHP intent, or
                (b) strip these 4 keys in handleSaveLabel before sending.

2. Label INSERT in electron/ipc/products.ts L207-212 omits is_active.
   New labels rely on schema default (1) so they default to active — fine,
   but the toggle in the dialog (L1108) has no effect on first save.
   Fix: include is_active in the INSERT column list.

3. drug_generic_name_id is selected in the UI (with its own autocomplete +
   antibiotic auto-tick side effect) but the value is never persisted —
   stripped at L220 because the column is missing from SQLite. Either add
   the column or remove the linked-ID display ("ID: {drug_generic_name_id}"
   at L635) so the UX doesn't suggest persistence.

4. unit_name (general tab) is edited as a free-text input but cannot be
   saved (column doesn't exist). To map a product to a base unit, the
   schema expects products.unit_id (FK). Either expose a unit picker or
   rely entirely on product_units rows for unit info.


==========================================================
NOTES / NON-ISSUES
==========================================================
- The strip-list at L220 (is_vat, is_not_discount, unit_name,
  drug_generic_name_id, has_wholesale1, has_wholesale2, default_qty)
  correctly prevents dynamic UPDATE failures for the general tab.
- has_vat / no_discount remap is correctly done after the destructure
  (the rename takes effect because the original is_vat / is_not_discount
  keys were destructured out and only the remapped names land in payload).
- Lot inline edit's user_id is consumed by the IPC handler for audit
  rows, not written to product_lots — that's intentional.
