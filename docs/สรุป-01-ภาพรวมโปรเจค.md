## Product Purpose

ระบบ **Pharmacy POS + คลังสินค้า + เอกสารกำกับยาตามกฎหมาย** สำหรับร้านขายยาในไทย rebuild จากแอป PHP (Laravel/MySQL) เดิม มาเป็น **Electron + React + SQLite** ที่รัน **offline เต็มตัว** บนเครื่องร้าน

**นิยามความสำเร็จ:** เภสัชกรสามารถ — ขายของหน้าร้าน, รับสต็อกพร้อม FEFO lot tracking ถูกต้อง, ตั้งราคาด้วยโมเดล 3 ต้นทุน, และออกรายงานที่ อย. กำหนด — ได้ครบ โดย**ไม่มี error และไม่ต้องต่อเน็ต**

## ผู้ใช้

พนักงานร้านยา + เจ้าของร้าน ร้านขนาดเล็ก-กลาง ใช้บนเดสก์ท็อป (Windows/Mac) 2 บริบทหลัก:

- **หน้าเคาน์เตอร์ (POS):** ขายเร็วด้วยคีย์บอร์ด + บาร์โค้ดสแกนเนอร์ ความเร็ว + ความแม่นยำ (zero-misclick) สำคัญกว่าความสวย มักยืนขายและมีคิวรอ
- **หลังร้าน (Manage / Purchase / Reports / Settings):** รับสต็อก (GR), จัดการ lot/FEFO, ตั้งราคา, ประวัติซื้อ, รายงานราชการ (ฟอร์ม ข.ย.), ข้อมูลลูกค้า, การเงิน

ผู้ใช้ไม่ใช่สาย tech หลายงานผูกกับภาระทางกฎหมาย (บันทึกยา อย.) → **ความถูกต้องและตรวจสอบย้อนได้สำคัญกว่าความแปลกใหม่**

## Brand Personality

สงบ แม่นยำ น่าเชื่อถือ คลินิคอลแต่อบอุ่น · สามคำ: **dependable, legible, unfussy** เป็นเครื่องมือใช้ทุกวัน ไม่ใช่ของโชว์ ควรรู้สึกเหมือนอุปกรณ์ที่ทำมาดี อัตลักษณ์ teal/yellow ให้ความอบอุ่นแบบคลินิคโดยไม่ขวางงาน

### Anti-references (สิ่งที่ตั้งใจหลีกเลี่ยง)
- หน้าตาแบบ Generic SaaS landing page (hero-metric, gradient, eyebrow ตัวเล็ก uppercase)
- ความ "สนุก" แบบ consumer fintech (illustration เล่นๆ, blob มน, confetti)
- พาเลต cream/sand/paper แบบ AI default → ของเราเป็น near-white neutral + teal โดยตั้งใจ
- motion เพื่อความสวย → animation ต้องรับใช้ task feedback เท่านั้น

## Design Principles (5 ข้อ)

1. **The task wins** — ทุกหน้ารับใช้งานหนึ่งอย่าง สวยแต่ช้าลง/เพิ่มคลิก = ผิด
2. **Density with legibility** — เครื่องมือ data-dense (ตาราง/lot/ราคา) แต่ห้ามต่ำกว่าเส้น legibility (สระไทยซ้อนต้องการ line-height)
3. **One source of truth for style** — หน้า `/theme` + semantic token system คุมหน้าตา ไม่มี styling ad-hoc
4. **Re-themable by one file** — เปลี่ยนพาเลตทั้งระบบได้ที่ `src/index.css` ไฟล์เดียว ห้าม hardcode สี (architectural guarantee)
5. **Correctness is visible** — สถานะ/สต็อก/แท็ก regulatory/ต้นทุน-กำไร แสดงด้วยสีตามบทบาท ไม่ซ่อน

## สถาปัตยกรรม

| Layer | ที่อยู่ |
|-------|---------|
| Electron main | `electron/main.ts` |
| IPC handlers | `electron/ipc/*.ts` |
| Database | `electron/db/` (index.ts, schema.ts, seed.ts) |
| Preload bridge | `electron/preload.ts` → `window.api` |
| React pages | `src/pages/` |
| UI components | `src/components/ui/` |
| Types | `src/types/index.ts` |
| Stores | `src/stores/` (cartStore, themeStore, userStore) |

### เอกสารละเอียดราย domain (อ่านก่อนแก้)
- `docs/claude/database.md` — schema, save/update, allow-listing, lookup tables
- `docs/claude/business-logic.md` — FEFO, GR, lot edit, pricing, walk-in, void, codes, label
- `docs/claude/ipc-api.md` — `window.api` namespaces
- `docs/claude/ui-theming.md` — สี, token, Button/Badge variants, dialog contract
- `docs/claude/ui-table-card.md` — layout ตาราง 4 zone, filter strip, row actions
- `docs/claude/ui-components.md` — showcase rule, Card, Tabs, Dialog, fonts
- `docs/claude/pos.md` — POS search modal focus/highlight, unit ordering

## โมเดล 3 ต้นทุน (สำคัญ)

- **`cost_price`** = ต้นทุนเฉลี่ยถ่วงน้ำหนัก (ใช้ valuation/รายงาน — ห้ามแก้มือ)
- **`last_cost_price`** = ต้นทุนล่าสุดที่จ่ายจริง (อ้างอิงตั้งราคา)
- **FEFO lot cost** = ต้นทุนของ lot นั้นๆ (กำไรของการขายครั้งนั้น)
