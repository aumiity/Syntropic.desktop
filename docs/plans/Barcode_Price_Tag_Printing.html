พิมพ์บาร์โค้ดสติ๊กเกอร์ + ป้ายราคา A4

Tab ใหม่ในหน้าสินค้า: พิมพ์สติ๊กเกอร์บาร์โค้ดบนกระดาษฉลากยาเดิม และป้ายราคาแผ่น A4 — เลือกสินค้า+หน่วยรายช่องบน grid พร้อม preview สด และอุดช่องโหว่ POS ให้สแกนบาร์โค้ดของหน่วยเจอ

เวอร์ชันแก้ไขตามเจ้าของ — 2026-06-10 (ปรับ 3 จุด)

  • 1. ที่อยู่ค่าตั้ง: เครื่องพิมพ์ + ขนาดกระดาษ มาจาก Settings เท่านั้น — สติ๊กเกอร์อ่านจาก label_settings (เครื่อง+กระดาษ width×height), ป้ายราคาอ่านจาก document_settings (เครื่อง + paper_size A4/A5 ที่ DocumentSettingsTab เลือกได้อยู่แล้ว — เลิก hardcode A4). ส่วน จำนวนดวง/ป้ายต่อแผ่น + การแสดงผล (ชื่อ/ราคา/บาร์โค้ด) ยังอยู่ ในหน้าพิมพ์ ตามเดิม (เป็น per-job control ที่ตั้งใจไว้ ไม่ใช่ deviation)
  • 2. เตือน fallback: เปลี่ยนจาก toast ชั่วคราว → ไอคอน TriangleAlert ติดบนช่องถาวร + Popover อธิบาย (อ่านได้ตลอด ไม่หายไปเอง); เคสไม่มีทั้งบาร์โค้ดและรหัส = ยัง block + toast error
  • 3. ขนาด/จำนวน: เลิกปรับ cols×rows/gap/ฟอนต์อิสระ → preset คงที่ "จำนวนดวงต่อแผ่น" (สติ๊กเกอร์ 1/2/4/6/8 ดวง, ป้ายราคา 4/8/12/24 ป้ายต่อ A4 — A5 ปรับลดตามส่วน) ที่คำนวณขนาดช่อง+ฟอนต์เหมาะสมไว้ให้; preset ที่เล็กเกินอ่านบนกระดาษนั้น = ปิดเลือก

1 ภาพรวม — ทำอะไร ทำไม

ตอนนี้แอปพิมพ์ได้แค่ฉลากยา — บาร์โค้ดสินค้ากับป้ายราคายังต้องไปทำมือข้างนอก แผนนี้เพิ่ม tab ที่ 3 ในหน้าสินค้า (/products/print) ที่มี 2 โหมดสลับกันได้:

  • สติ๊กเกอร์บาร์โค้ด — ใช้เครื่องพิมพ์+กระดาษตัวเดียวกับฉลากยา (อ่านจาก label_settings ตรง ๆ ไม่ตั้งซ้ำ); เลือก preset จำนวนดวงต่อแผ่น (1/2/4/6/8 ดวง) แต่ละช่องเลือกสินค้า+หน่วยอิสระ
  • ป้ายราคา — ใช้เครื่องพิมพ์เอกสารเดิม + ขนาดกระดาษจาก document_settings.paper_size (A4/A5); เลือก preset จำนวนป้ายต่อแผ่น (A4: 4/8/12/24) ราคาตัวใหญ่ มีเส้นตัด

ทั้งสองโหมดใช้ UX เดียวกัน: เลือก preset จำนวนต่อแผ่น → คลิกช่อง → ค้นหาสินค้า → เลือกหน่วย, ปุ่ม "คัดลอกช่องแรกไปทุกช่อง", ช่องว่างเว้นได้, จำนวนสำเนา, preview สดเหมือนของจริง. เครื่องพิมพ์+ขนาดกระดาษมาจาก Settings (สติ๊กเกอร์=ฉลากยา, ป้ายราคา=เอกสาร A4/A5); preset จำนวนต่อแผ่น + การแสดงผล (ชื่อ/ราคา/บาร์โค้ด) อยู่ในหน้าพิมพ์ (จำค่าล่าสุดไว้)

ระหว่าง audit พบของแถมสำคัญ: POS ปัจจุบันสแกนบาร์โค้ดของ "หน่วย" (แผง/กล่อง) ไม่เจอเลย เพราะ pos:searchProducts ไม่ค้น product_units.barcode — ถ้าไม่อุด พิมพ์สติ๊กเกอร์หน่วยไปก็สแกนไม่ได้ แผนนี้จึงรวม Step 2.5 แก้จุดนี้ด้วย

3 ก่อน ↔ หลัง

ก่อน

  • พิมพ์บาร์โค้ดสินค้า/ป้ายราคาในแอปไม่ได้เลย — ต้องทำมือใน Word/Excel ข้างนอก
  • เครื่องพิมพ์ฉลากใช้ได้กับฉลากยาอย่างเดียว
  • สแกนบาร์โค้ดของหน่วย (แผง/กล่อง) ใน POS ไม่เจอ — pos:searchProducts ค้นเฉพาะบาร์โค้ดบนตัวสินค้า
  • ค้นหาสินค้าใน dialog อื่น ๆ (Quotation) ไม่มี keyboard nav

หลัง

  • Tab "พิมพ์บาร์โค้ด/ป้ายราคา" ใน /products — สติ๊กเกอร์ grid บนกระดาษฉลากยาเดิม + ป้ายราคา A4 พร้อมเส้นตัด
  • เลือกสินค้า+หน่วยรายช่อง, copy ช่องแรกไปทุกช่อง, preview สดตรงกับงานพิมพ์ 100% (builder เดียวกัน)
  • ค่าตั้ง layout จำไว้ใน DB — ปิดเปิดแอปไม่หาย, staff ใช้ได้ไม่ติดสิทธิ์
  • สแกนบาร์โค้ดหน่วยใน POS เจอ + highlight หน่วยถูกต้อง ราคาตรงป้าย

4 ส่งผลอย่างไร

ข้อดี

  • Reuse โครงเดิมเกือบทั้งหมด — printer:printLabel, LABEL_FIT_SCRIPT (shrink-to-fit รายช่องได้ฟรี), barcodeSvg (EAN13/EAN8/CODE128 อัตโนมัติ), ฟอนต์ฝัง data-URI — ไม่มี dependency ใหม่ ไม่ต้อง npm install
  • แก้ช่องโหว่ POS ที่มีมาก่อน (สแกนบาร์โค้ดหน่วยไม่เจอ) แบบ backward-safe — ผลค้นหาเดิมไม่เปลี่ยน แค่ได้เพิ่ม
  • Preview = HTML ตัวเดียวกับที่พิมพ์จริง (iframe srcDoc) — สิ่งที่เห็นคือสิ่งที่ได้ ไม่มี drift
  • ตาราง DB ใหม่เป็น additive ล้วน — rollback ง่าย ไม่แตะข้อมูลเงิน/สต็อก

ข้อเสีย / ต้นทุน

  • แตะไฟล์ shared 2 จุด: ProductSearchDialog (เพิ่ม prop ใหม่) และ WAIT_FOR_RENDER_JS ใน printer.ts — ต้อง regression ใบเสร็จ/เอกสาร A4 เดิมตอน click-test
  • การแบ่งหน้าที่: เครื่องพิมพ์+ขนาดกระดาษ อยู่ Settings (label_settings/document_settings เดิม), ส่วน จำนวนดวงต่อแผ่น + การแสดงผล อยู่ในหน้าพิมพ์ (per-job, จงใจ — operational ของหน้าร้าน ไม่ใช่ config ระดับระบบ)
  • save preset/toggle 2 ตัวนี้ไม่ gate admin (จงใจ — staff เป็นผู้ใช้หลัก + auto-persist จำค่าล่าสุด) ต่างจาก settings writes ตัวอื่น — มี carve-out ใน doc กำกับ

ข้อควรระวัง

  • POS invariants: base unit ต้องเป็นแถวแรกเสมอ (ห้าม reorder), highlight เป็นของ keyboard เท่านั้น — Step 2.5 เปลี่ยนแค่ "ค่าตอน reset" ผ่าน prop ใหม่ ห้ามเพิ่ม mouse path
  • Dynamic SQL save: key ของ form ต้องตรงชื่อ column เป๊ะ ไม่งั้น UPDATE ทั้งก้อนพัง — สร้าง state จาก DEFAULTS ที่ตรง column เท่านั้น
  • บาร์โค้ด fallback: หน่วยที่ไม่มีบาร์โค้ดตัวเองจะพิมพ์บาร์โค้ดหน่วยพื้นฐานแทน → สแกนแล้วได้ราคาหน่วยพื้นฐาน ไม่ตรงป้าย — ระบบเตือนด้วย ไอคอน TriangleAlert ติดบนช่องถาวร + Popover อธิบาย (อยู่จนกว่าจะแก้ ไม่หายไปเองเหมือน toast)
  • กระดาษเล็ก ÷ จำนวนดวงมาก = ช่องเล็กอ่านไม่ออก — กันด้วย preset คงที่ที่คำนวณขนาดช่องไว้ล่วงหน้า: preset ที่ทำให้ช่องเล็กกว่าเกณฑ์อ่านออกบนกระดาษนั้น = ปิดเลือก (disabled + เหตุผล) จึงเลือกได้เฉพาะขนาดที่ใช้งานได้จริง

5 UX / UI

  • Bar บน (h-12): ซ้าย = สลับโหมดด้วย Tabs variant toggle (สติ๊กเกอร์บาร์โค้ด / ป้ายราคา A4); ขวา = ช่องจำนวนสำเนา + ปุ่ม "ดูตัวอย่าง PDF" (elevated) + ปุ่ม "พิมพ์" (default — primary teal) ทุกตัว h-9
  • ซ้าย: SectionCard "ตั้งค่า" (preset จำนวนดวง/ป้ายต่อแผ่น — segmented/Select, preset ที่เล็กเกินบนกระดาษปัจจุบัน disabled + toggle การแสดงผล ชื่อ/ราคา/บาร์โค้ด — auto-save ไม่มีปุ่มบันทึก; ไม่มีช่อง cols/rows/gap/ฟอนต์อิสระแล้ว) + SectionCard "สินค้าในแผ่น" (GridEditor); ขวา: preview สด พร้อมป้ายบอกเครื่องพิมพ์+ขนาดกระดาษที่ใช้ (อ่านจาก Settings, read-only)
  • GridEditor: ช่องว่าง = กรอบ dashed + ไอคอน Plus "เลือกสินค้า"; ช่องมีของ = ชื่อ/หน่วย/ราคา + ปุ่ม X ลบ; เคส fallback (barcode_source !== 'own') = ไอคอน TriangleAlert สี warning มุมช่อง → คลิก/ชี้เปิด Popover อธิบาย ("บาร์โค้ดหน่วยพื้นฐาน — สแกนแล้วได้ราคาหน่วยพื้นฐาน" / "ใช้รหัสสินค้าแทนบาร์โค้ด"); ปุ่ม "คัดลอกช่องแรกไปทุกช่อง" (primary-soft) + "ล้างทั้งหมด" (outline)
  • ค้นหาสินค้า: ใช้ search modal ตัวเดียวกับ POS (ProductSearchDialog) — ลูกศรขึ้นลง + Enter เลือก + Esc ปิด, แถวหน่วยพื้นฐานมาก่อนเสมอ, โชว์บาร์โค้ด/รหัสในแถวให้รู้ก่อนเลือก
  • แสดงชื่อเครื่องพิมพ์ที่จะใช้แบบ read-only — ค่าว่าง = "เครื่องพิมพ์เริ่มต้นของระบบ" (ไม่ใช่ error); เตือนเฉพาะเครื่องที่ตั้งไว้แล้วหายไป
  • เมื่ออยู่ tab นี้ MetricCards 4 ใบ + ปุ่ม "เพิ่มสินค้า" ของหน้า Products ซ่อน — พื้นที่เต็มสำหรับงานพิมพ์
  • ภาษาไทยทั้งหมด, semantic tokens เท่านั้น, ไอคอน lucide (Tags สำหรับ tab), toast ผ่าน useToast()

    Step 1 — Schema: 2 ตาราง singleton ใหม่ (electron/db/schema.ts)

    วาง CREATE TABLE IF NOT EXISTS ต่อจาก document_settings (ปิดวงเล็บที่ :572) ตาม pattern พี่น้อง (receipt_settings/document_settings):

    -- Barcode sticker print-page preference (singleton). Printer + paper (W×H)
-- come from label_settings (same physical printer + die-cut paper as drug
-- labels). This table only stores the chosen LAYOUT PRESET + content toggles.
-- preset resolves to {cols,rows,gap,font sizes,barcode height} via
-- src/lib/tags/presets.ts (cell size COMPUTED from the actual label paper;
-- presets too small for the paper are disabled in the UI). Columns map 1:1 to
-- the renderer form keys (dynamic-SQL save).
CREATE TABLE IF NOT EXISTS barcode_sticker_settings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  preset      TEXT NOT NULL DEFAULT '4up',   -- '1up'|'2up'|'4up'|'6up'|'8up' (ดวงต่อแผ่น) → grid+ฟอนต์ใน presets.ts
  show_name   INTEGER NOT NULL DEFAULT 1,
  show_price  INTEGER NOT NULL DEFAULT 1,
  show_digits INTEGER NOT NULL DEFAULT 1,
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- Price-tag print-page preference (singleton). Printer + paper SIZE (A4/A5)
-- come from document_settings (printer_name + paper_size). This table only
-- stores the chosen LAYOUT PRESET + content toggles. preset resolves per paper
-- size via src/lib/tags/presets.ts (e.g. A4 '8up' = 2×4; A5 fewer).
CREATE TABLE IF NOT EXISTS price_tag_settings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  preset         TEXT NOT NULL DEFAULT '8up', -- '4up'|'8up'|'12up'|'24up' (ป้ายต่อ A4) → grid+ฟอนต์ใน presets.ts
  show_name      INTEGER NOT NULL DEFAULT 1,
  show_price     INTEGER NOT NULL DEFAULT 1,
  show_barcode   INTEGER NOT NULL DEFAULT 0,
  show_code      INTEGER NOT NULL DEFAULT 0,
  show_unit      INTEGER NOT NULL DEFAULT 1,
  show_cut_lines INTEGER NOT NULL DEFAULT 1,
  font_family    TEXT NOT NULL DEFAULT 'Sarabun',
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
    • ตารางใหม่ทั้งคู่ → ไม่ต้องมี ALTER migration (CREATE IF NOT EXISTS รันทุก boot)
    • Invariant: form keys = column names เป๊ะ (dynamic SQL UPDATE จาก Object.keys) → docs/claude/database.md
