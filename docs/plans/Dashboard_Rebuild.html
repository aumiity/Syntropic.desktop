รื้อ Dashboard — รวมสรุปขาย/ซื้อไว้ที่เดียว

ย้ายแผงภาพรวมการเงินออกจาก Manage › ขาย/ซื้อ ไปยุบรวมที่หน้า Dashboard (/reports) เป็น 3 ส่วน แล้วคืนหน้า Manage ให้ admin เห็นเท่ากับ staff เป๊ะ

ผ่าน audit 2 รอบ · ไม่มี blocker renderer-only · ไม่แตะ IPC/schema 2026-06-29

1 ภาพรวม — ทำอะไร ทำไม

ปัญหา: ตอนนี้แผงสรุปการเงิน (การ์ดยอด + กราฟ trend + การ์ดสถานะ) ฝังอยู่ในหน้า Manage › ขายสินค้า และ Manage › การซื้อ เฉพาะตอนเป็น admin — ทำให้หน้าประวัติสองหน้านี้หน้าตาต่างกันระหว่าง admin กับ staff และตัวเลขสรุปกระจัดกระจาย ไม่ได้อยู่รวมกับ Dashboard ที่ก็มีตัวเลขคล้าย ๆ กันอยู่แล้ว (ทับซ้อน)

แผนนี้: รื้อหน้า Dashboard (/reports แท็บ "แดชบอร์ด") ใหม่ทั้งหมด ยุบรวมของเดิม + แผงจาก Manage เป็น 3 ส่วนเรียงบนลงล่าง — (1) ภาพรวมร้าน/สต็อก, (2) สรุปการขาย, (3) สรุปการซื้อ — คุมด้วยตัวเลือกช่วงเวลาตัวเดียวทั้งหน้า แล้วถอดแผงการเงินออกจาก Manage ทั้งสองหน้า ให้ทุก role เห็นแค่การ์ดนับจำนวน + ตารางประวัติ (admin = staff เป๊ะ)

เสร็จแล้วได้: Dashboard เดียวที่เล่าเรื่อง ขาย/ซื้อ/สุขภาพร้าน ครบในที่เดียว · หน้า Manage กลับมาเบา เป็นตารางล้วน ๆ เท่ากันทุก role · ไม่แตะ backend เลย (ใช้ IPC เดิมทั้งหมด ความเสี่ยงต่ำ)

3 ก่อน ↔ หลัง

ก่อน

  • Dashboard: KPI 5 การ์ด → กราฟ+โดนัท+แจ้งเตือน → ขายดี/กำไร/ค่าใช้จ่าย → พนง./ผู้จัดจำหน่าย/ลูกค้า (เนื้อหาทับซ้อนกับ Manage)
  • Manage ขาย/ซื้อ (admin): แผงการเงินเต็ม + ทั้งหน้าเลื่อนรวมกัน (scrollPage + forward-wheel)
  • Manage ขาย/ซื้อ (staff): การ์ดนับ + ตารางเต็มจอ
  • admin กับ staff เห็น Manage ต่างกัน
  • 2 หน้ายิง financeSummary/salesPurchaseTrend แยกกันเอง

หลัง

  • Dashboard: 3 ส่วนชัดเจน (ภาพรวมร้าน/สต็อก → ขาย → ซื้อ) picker ตัวเดียวคุมทั้งหน้า
  • Manage ขาย/ซื้อ: การ์ดนับ + ตาราง — เหมือนกันทุก role (admin = staff)
  • ไม่มี scrollPage/forward-wheel ใน Manage แล้ว — กลับเป็นการ์ดสูงคงที่
  • โดนัท + กราฟเลื่อน 7/30/90 หาย → แถบสถานะ + กราฟอิง picker
  • ตัวเลขการเงินทั้งหมดอยู่ที่ Dashboard ที่เดียว

4 ส่งผลอย่างไร

ข้อดี

  • ตัวเลขสรุปอยู่รวมกันที่เดียว เล่าเรื่องครบ ขาย/ซื้อ/สุขภาพร้าน
  • หน้า Manage เบาลง สม่ำเสมอทุก role — ลดความซับซ้อน (ตัด scrollPage/forward-wheel/animation-สำหรับ-scroll)
  • ไม่แตะ IPC/schema เลย — เป็นการ "ย้ายโค้ดที่ผ่าน e2e แล้ว" + strip ความเสี่ยงต่ำ
  • กราฟทั้งสองส่วนอิง picker เดียว granularity อัตโนมัติ สอดคล้องกันทั้งหน้า

ข้อเสีย / ต้นทุน

  • หน้า Dashboard ยาวขึ้น (3 ส่วน) ต้องเลื่อนมากกว่าเดิม — ใช้ scroll ของ ReportsLayout เดิม ไม่ต้องทำกลไกใหม่
  • ยิง IPC พร้อมกัน ~11–12 ตัวต่อการโหลด (เพิ่ม purchase.history 1 ตัวจากของเดิม) — รับได้
  • โดนัทสัดส่วนการขายหายไป (เจ้าของเลือกรวมเป็นแถบสถานะอันเดียว)

ข้อควรระวัง

  • recharts Tooltip ชนชื่อกับ UI Tooltip — ลบ import recharts ทั้งบรรทัด (โดนัทหายแล้ว) ก่อนเพิ่ม UI tooltip ไม่งั้น tsc พัง
  • อย่าลบ motion ใน Purchases.tsx — ยังใช้ใน edit-dialog pill (บรรทัด ~1086-1136) ไม่ใช่แผง finance
  • เก็บ Percent ทั้งสองหน้า — เป็นปุ่มกรอง VAT คนละที่กับแผง
  • ห้าม emoji ในโค้ด/UI · ใช้ semantic token เท่านั้น (ห้าม bg-blue-500) · scrollbar thin 7px · bar=h-12/control=h-9 · วันที่ผ่าน formatDate() ค.ศ. DD/MM/YYYY (ลบ rangeLabel แบบ พ.ศ. ทิ้ง)
  • render helper ตัวเล็ก (lowercase) ใน Dashboard.tsx โอเค (เหมือน payRow/divider เดิม) — ห้ามทำเป็น component ตัวใหญ่ในไฟล์ page

5 UX / UI

หน้า Dashboard: 3 ส่วนเรียงบนลงล่าง คั่นด้วยหัวข้อส่วน (render helper sectionHeading — ไอคอน lucide + ข้อความ text-base font-semibold + เส้นคั่นบาง) ทุกส่วนใช้ SectionCard/MetricStrip/TrendChart/TopListCard ตาม /theme เดิม สี tint ตาม role: ขาย=primary/success, ซื้อ=primary/amber/violet, แจ้งเตือน=destructive/warning/amber/info-soft. ปุ่มสลับในการ์ด (ขายดี/กำไร) ใช้ variant="elevated" ตามเดิม. การ์ดสถานะ = แถบสัดส่วน + legend + hover เชื่อมแถบ↔legend (ยกมาจาก Manage). ภาษาไทยทั้งหมด.

Toolbar: MultiDatePicker + ปุ่มรีเฟรช อยู่ใน toolbar ของ ReportsLayout (เดิม) คุมทุกส่วนยกเว้นแจ้งเตือน (ไม่ผูกเวลา) และการ์ดค่าใช้จ่าย (dropdown เดือนนี้/เดือนที่แล้ว/ปีนี้ ของตัวเอง).

หน้า Manage ขาย/ซื้อ: ทุก role เห็นเหมือนกัน — การ์ดนับจำนวน (5 ของขาย, 6 ของซื้อ) ในสล็อต summary + ตารางประวัติเต็มจอ + ตัวกรอง/ค้นหา/picker เดิมครบ ไม่มีแผงการเงิน. staff ไม่เห็นเมนูรายงาน/Dashboard อยู่แล้ว (gate ด้วย report.finance) — ไม่ต้องทำ path staff เพิ่ม.
