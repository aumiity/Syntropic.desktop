รื้อ Dashboard v2 — "ศูนย์บัญชาการ"

เขียนใหม่จาก mockup ที่เคาะแล้ว (Dashboard_Rebuild_Mockup.html) + ผลสำรวจ backend จริง 3 สาย — แทบไม่แตะ backend, ของใหม่จริงมีแค่ 2 ชิ้น (กราฟ diverging + การ wire ตารางแจ้งเตือน)

SSOT = mockup ที่เคาะแล้ว สำรวจ backend แล้ว: ตัวเลขครบ 100% renderer-only ยกเว้น 1 component ใหม่ 2026-06-29 (v2)

1 ภาพรวม — ทำอะไร ทำไม

ที่มา: แผนเดิม (v1) วางไว้เป็น "3 ส่วนเรียงบนลงล่าง (สต็อก→ขาย→ซื้อ)" แต่หลังทำ mockup กับเจ้าของหลายรอบ หน้าตากลายเป็น "ศูนย์บัญชาการ" จัดตามหัวข้อ ไม่แบ่งบล็อกขาย/ซื้อแล้ว — แผนนี้ (v2) จึงเขียนใหม่ทั้งฉบับให้ตรง mockup สุดท้าย

แผนนี้: รื้อ src/pages/Reports/Dashboard.tsx ใหม่ทั้งหมดเป็น 5 บล็อกเรียงบนลงล่าง (ไม่มีหัวข้อ band คั่น) คุมด้วย MultiDatePicker ตัวเดียวทั้งหน้า แล้ว ถอดแผงการเงินออกจาก Manage ขาย/ซื้อ (Phase B) ให้ตัวเลขการเงินอยู่ที่ Dashboard ที่เดียว และ Manage กลับเป็นตารางล้วน admin=staff

สำรวจ backend แล้ว (3 สาย): ตัวเลขทุกจุดมีฟิลด์รองรับครบ (financeSummary มี expense_total/selling_days/previous ครบ) · ตารางแจ้งเตือน 4 หมวดมี IPC คืน rows + route หน้าเต็มครบ · กราฟ diverging ต้อง สร้าง component ใหม่ (recharts เดิมทำ stack/เส้นศูนย์ไม่ได้ แต่ recharts รองรับในตัว สร้างไม่ยาก)

2 โครงหน้า — 5 บล็อก, picker เดียวคุมทั้งหน้า

บล็อกเนื้อหาแหล่งข้อมูล
1. MetricStrip (6 ช่อง)ยอดขาย · ต้นทุน · กำไร(+%กำไร) · ยอดซื้อ · ค้างชำระ · ค่าใช้จ่ายอื่นๆ — tint icon ชิดขวาบนทุกช่อง, delta vs ช่วงก่อนfinanceSummary (ตาม picker หลัก ทุกช่องรวมค่าใช้จ่าย)
2. กราฟ + การขายซ้าย = ใหม่ DivergingTrendChart (ยอดขายพุ่งขึ้น+กำไรซ้อนใน / ยอดซื้อพุ่งลงติดลบ / เส้นศูนย์ / แกน Y) · ขวา = การ์ด "การขาย" (แถบสถานะ ปลีก/ส่ง/คืน/ยกเลิก + เฉลี่ย/บิล·/วัน)salesPurchaseTrend · salesStats · financeSummary
3. อันดับ + สรุปซื้อสินค้าขายดี · กำไรสูงสุด · การ์ด "การซื้อ" (แถบสถานะ เงินสด/ชำระแล้ว/ค้างชำระ/เกินกำหนด/ยกเลิก)topProducts ×2 · purchase.history summary
4. ทีม + ค่าใช้จ่ายผู้จัดจำหน่าย · พนักงานขาย · ค่าใช้จ่ายอื่นๆ (การ์ดแยกหมวด มี dropdown ช่วงเวลาของตัวเอง)topSuppliers · cashierLeaderboard · expenses.list
5. แจ้งเตือน + ตารางซ้าย = 4 tiles (กดเป็นตัวกรอง) · ขวา = ตารางมาตรฐาน (rows ของหมวดที่เลือก, elevated icon, footer pagination ‹›, ปุ่ม "เปิดตารางเต็ม"→หน้า Manage)tiles: counts · ตาราง: IPC ต่อหมวด

ไม่มีหัวข้อ band คั่นระหว่างบล็อก (เจ้าของเลือกตัดออก) — เว้นช่องว่างแทน · ทุกบล็อกมี loading state

3 ผลสำรวจ backend (3 สาย)

เรื่องสถานะรายละเอียด
financeSummary / salesStats / purchase.historyพร้อม 100%ทุกตัวเลขใน KPI + การ์ดขาย/ซื้อ มีฟิลด์ครบ — รวม expense_total, selling_days, sales_discount, previous{}. ค่าเฉลี่ย/% คำนวณฝั่ง renderer ได้หมด
ตารางแจ้งเตือน 4 หมวดพร้อม (ต่อ wiring)ติดลบ=negativeStock:list · ต่ำกว่าจุดสั่ง=products:lowStock · ใกล้หมดอายุ=reports:expiringLots (paginate เองได้) · ค้าง 6 ด.=reports:inactiveProducts. Route /manage/{negative-stock,low-stock,expiry,dead-stock} ครบ
กราฟ divergingสร้างใหม่TrendChart เดิม: ไม่มี stackId (stack ไม่ได้), ไม่มี ReferenceLine y=0. แต่เป็น recharts อยู่แล้ว ซึ่งรองรับ stack + เส้นศูนย์ + ค่าติดลบ → สร้าง DivergingTrendChart ใหม่

Data fetching (Dashboard ใหม่)

  • financeSummary({ date_from, date_to, with_compare:true, ...prevWindowForMode(mode,from,to) }) → KPI 6 ช่อง + การขาย(selling_days/discount) + การซื้อ(payable)
  • salesStats({date_from,date_to}) → counts ปลีก/ส่ง/คืน/ยกเลิก/all (การ์ดการขาย)
  • salesPurchaseTrend({ date_from, date_to, granularity: granularityForMode(mode) }) → DivergingTrendChart (ป้อน sales_net/sales_cost/sales_profit/purchase_total)
  • purchase.history({ date_from, date_to, limit:1 }) → res.summary (การ์ดการซื้อ; duenow=max(0,unpaid_count-overdue_count))
  • topProducts({by:topSortBy,limit:5}) + topProducts({by: profitMode==='pct'?'margin':'profit',limit:5}) · topSuppliers({limit:5}) · cashierLeaderboard({limit:5})
  • alert counts (ไม่ผูกเวลา): negativeStock:count, products.lowStock({}), expiringLots({count_only:true}), inactiveCounts()
  • alert rows (ตาม selectedAlert): negativeStock:list / products.lowStock({}) / expiringLots({filter:30,limit:8,page}) / inactiveProducts({limit:50}) — neg/low/dead คืน list เต็ม → slice client; exp paginate server ได้แต่ slice client ก็พอ
  • expenses (การ์ดแยกหมวด own period): expenses.list({date_from,date_to,pageSize:0}) ×2 (cur+prev) — verbatim จาก Dashboard เดิม
