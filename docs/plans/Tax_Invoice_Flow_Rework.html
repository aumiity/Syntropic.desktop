คิด flow การพิมพ์ใบกำกับภาษีใหม่

ออกใบกำกับภาษีเต็มรูปจากรายงานภาษีขาย · เลือกผู้ซื้อจากลูกค้าในระบบ · ไม่แปลง VAT ย้อนหลัง

ร่าง · ผ่าน audit 2 รอบ VAT / ใบกำกับภาษี 2026-06-12

1 ภาพรวม — ทำอะไร ทำไม

ตอนนี้การออกใบกำกับภาษีเต็มรูปมีปัญหา 3 จุดที่ทำให้ใช้งานจริงลำบาก:

  • หาบิล VAT ไม่เจอ — ไม่มีตารางไหนแสดงสถานะ VAT ให้กรอง/ค้นหา เวลาลูกค้ามาขอใบย้อนหลังต้องไล่เปิดทีละบิล
  • ต้องพิมพ์ข้อมูลผู้ซื้อเองทุกครั้ง — กล่องออกใบกำกับ prefill มาแค่ "ชื่อ" ไม่มีตัวเลือกดึงลูกค้าที่มีอยู่แล้วมาใช้ (ที่อยู่/เลขภาษี/สาขา ต้องพิมพ์ใหม่หมด)
  • ลูกค้ายังเก็บเลขผู้เสียภาษีไม่ได้ — ตาราง customers ไม่มีช่อง tax_id/branch เลย ต่อให้เลือกลูกค้าก็ไม่มีเลขภาษีให้ดึง

แผนนี้แก้โดย: เพิ่ม ปุ่มออกใบกำกับ/พิมพ์สำเนา ต่อแถว ในตาราง "รายงานภาษีขาย" ที่ /reports/vat (ไม่สร้างตารางใหม่ เพราะเป็นข้อมูลชุดเดียวกัน), เพิ่ม ตัวเลือกลูกค้าจากระบบ ในกล่องออกใบกำกับที่ดึงชื่อ/ที่อยู่/เลขภาษี/สาขามาให้อัตโนมัติ, เพิ่มช่อง tax_id+branch เข้าตารางลูกค้าและฟอร์มลูกค้า, และเมื่อแก้ข้อมูลผู้ซื้อตอนออกใบครั้งแรก จะ บันทึกกลับไปที่ลูกค้าให้อัตโนมัติ (ครั้งหน้าไม่ต้องพิมพ์ซ้ำ)

เรื่อง VAT ย้อนหลัง: บิลที่ขายแบบ "ไม่เอา VAT" ไปแล้ว ไม่แปลงย้อนหลัง — ถ้าลูกค้าขอใบกำกับทีหลัง ใช้วิธี ยกเลิกบิลเก่า แล้วขายใหม่เป็นบิล VAT (ปลอดภัยทางภาษี กันคนหายไปหลายวันแล้วเพิ่งนึกได้). เงื่อนไขเดิม "ออกใบได้เฉพาะบิล total_vat > 0" ถูกต้องอยู่แล้ว คงไว้

3 ก่อน ↔ หลัง

ก่อน

  • หาบิล VAT ไม่ได้ — ไม่มีตารางแสดงสถานะ VAT
  • ออกใบกำกับได้จาก kebab ใน Manage/Sales เท่านั้น
  • กล่องออกใบ prefill มาแค่ "ชื่อ" — ที่อยู่/เลขภาษี/สาขา พิมพ์เองทุกครั้ง
  • ลูกค้าเก็บเลขผู้เสียภาษีไม่ได้ (ไม่มีช่อง)
  • ไม่รู้ว่าบิลไหนออกใบกำกับไปแล้ว

หลัง

  • ตาราง "รายงานภาษีขาย" = รายการบิล VAT ทั้งหมด ค้นหา/กรองช่วงวันได้
  • ปุ่มต่อแถว: ออกใบกำกับ (ยังไม่ออก) / พิมพ์สำเนา (ออกแล้ว)
  • เลือกลูกค้าจากระบบ → ดึงชื่อ/ที่อยู่/เลขภาษี/สาขามาให้ครบ
  • ลูกค้ามีช่อง tax_id + สาขา; แก้ตอนออกใบครั้งแรกบันทึกกลับให้
  • kebab เดิมยังอยู่เป็นทางลัด · VAT ย้อนหลัง = ยกเลิก+ขายใหม่

4 ส่งผลอย่างไร

ข้อดี

  • ออกใบกำกับ + ตามสถานะ "ออกแล้ว/ยังไม่ออก" ได้จากที่เดียว ไม่ต้องไล่เปิดบิล
  • ไม่ต้องพิมพ์ข้อมูลผู้ซื้อซ้ำ — ดึงจากลูกค้าในระบบ + จำให้ครั้งต่อไป
  • ไม่สร้างตารางใหม่ — ใช้รายงานภาษีขายที่มีอยู่ (ข้อมูลชุดเดียวกัน)
  • ไม่มีช่องโหว่ภาษี: ไม่แปลง VAT ย้อนหลัง, เงื่อนไข total_vat>0 คงเดิม

ข้อเสีย / ต้นทุน

  • เพิ่ม migration 2 คอลัมน์ใน customers (nullable, ปลอดภัย แต่เป็นการแก้ schema)
  • vatSummary salesRows query ยาวขึ้น (join customers + tax_invoices)
  • ลูกค้าเก่าที่ import มา (Hygeia) จะยังไม่มี tax_id จนกว่าจะกรอก/ออกใบครั้งแรก

ข้อควรระวัง (invariant)

  • Allow-list payload: handler บันทึกกลับใช้คอลัมน์ระบุชัด ไม่ spread Object.keys
  • ลูกค้าทั่วไป C0000: picker ปิด walk-in (showWalkIn={false}) + handler กัน walkInCustomerId
  • บันทึกกลับเฉพาะออกครั้งแรก (!copy) + ที่อยู่เขียนเฉพาะตอนว่าง — กันเขียนทับข้อมูลลูกค้าที่ดีอยู่แล้ว
  • ปุ่ม row-action = square size="icon-lg" variant="elevated" + tooltip (ห้าม size=sm/ป้ายข้อความ/role-tint) ตาม ui-table-card.md
  • แก้เฉพาะไฟล์ .ts — ไฟล์ electron/ipc/*.js ที่ track ไว้เป็น artifact เก่า ไม่ใช่ runtime

5 UX / UI

  • ตารางรายงานภาษีขาย — เพิ่มคอลัมน์ท้าย "ใบกำกับภาษี" ปุ่มไอคอนสี่เหลี่ยม elevated ต่อแถว: ยังไม่ออก = ไอคอน FileText tooltip "ออกใบกำกับภาษี"; ออกแล้ว = ไอคอน Copy tooltip "พิมพ์สำเนาใบกำกับ" (neutral elevated ไม่ใส่สีบทบาท)
  • กล่องออกใบกำกับ — เพิ่มปุ่ม "เลือกลูกค้าจากระบบ" บนสุดของ body → เปิด CustomerSearchDialog (ไม่มี walk-in) เลือกแล้ว prefill ชื่อ/ที่อยู่/เลขภาษี/สาขา; ลูกค้าใหม่ที่ยังไม่มีในระบบ พิมพ์เองได้เหมือนเดิม; ปุ่มท้าย "ดูตัวอย่าง PDF" (elevated) + "พิมพ์ใบกำกับภาษี" (default) ตามเดิม
  • ฟอร์มลูกค้า — เพิ่ม 2 ช่องใต้ที่อยู่: "เลขประจำตัวผู้เสียภาษี (13 หลัก)" (กรอกได้เฉพาะตัวเลข) + "สาขา" (placeholder สำนักงานใหญ่) ใช้ Input variant="elevated" + Label เหมือนช่องอื่น
  • ภาษาไทยทั้งหมด ไม่มี emoji · ใช้ semantic token · ไอคอน lucide · ปฏิบัติตาม modal contract เดิมของ Dialog
