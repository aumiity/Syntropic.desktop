มูลค่าสินค้าคงคลัง (Inventory Valuation)

แท็บใหม่ "มูลค่าคงคลัง" เป็นแท็บแรกสุดใต้ การจัดการ › สต็อคสินค้า — แสดงมูลค่ารวมของสินค้าทั้งหมดที่มีในคลัง (ทุน + ราคาขาย + กำไรคงค้าง) เฉพาะผู้มีสิทธิ์เห็นต้นทุน

1 ภาพรวม — ทำอะไร ทำไม

ปัญหา: ตอนนี้แอปคำนวณมูลค่าสต็อกได้ (qty × ต้นทุน) แต่ไม่มีจุดไหนรวมยอด ทุกตัวในคลัง ให้ดูในที่เดียว — มูลค่าโผล่เฉพาะแบบกรองเงื่อนไขในแท็บ "ค้างสต็อก" และ "วันหมดอายุ" เท่านั้น

แผนนี้แก้: เพิ่มแท็บ "มูลค่าคงคลัง" เป็น sub-tab แรกสุดของ "สต็อคสินค้า" รวมมูลค่าสินค้าทั้งหมดที่ยังมีของในล็อตเปิด (is_closed=0, จำนวนคงเหลือ > 0) แสดงเป็นการ์ดสรุปด้านบน + ตารางรายสินค้าเรียงจากมูลค่ามากไปน้อย กรองตามหมวดและค้นชื่อได้

เสร็จแล้วได้: เปิดแท็บเดียวเห็น "เงินจมในสต็อกตอนนี้เท่าไหร่" ทันที ทั้งมูลค่าต้นทุน มูลค่าตามราคาขาย และส่วนต่าง (กำไรที่ยังไม่ขาย) — ข้อมูลเป็นความลับทางการเงิน จึงเปิดให้เฉพาะคนที่มีสิทธิ์ "เห็นต้นทุน" (เจ้าของ/เภสัช) พนักงานทั่วไปจะไม่เห็นแท็บนี้เลย

เลย์เอาต์มิเรอร์หน้า "ค้างสต็อก" — 4 zone ตามมาตรฐาน table-card (filter strip h-12 / column header / rows / status bar) · การ์ดสรุปยิงผ่าน setSummary เหมือนแท็บพี่น้อง

3 ก่อน ↔ หลัง

ก่อน

  • ไม่มีจุดดูมูลค่าคงคลัง รวมทั้งหมด
  • มูลค่าโผล่เฉพาะแบบกรอง: "ค้างสต็อก" (มูลค่าทุนรวม) + "วันหมดอายุ" (มูลค่าทั้งหมด)
  • อยากรู้เงินจมในสต็อกต้องเดา/ส่งออก Excel มานับเอง
  • สต็อคสินค้า มี 4 sub-tab: ค้างสต็อก · วันหมดอายุ · ต่ำกว่าจุดสั่งซื้อ · ติดลบ

หลัง

  • แท็บ "มูลค่าคงคลัง" เป็นอันแรก เปิดเห็นยอดรวมทันที
  • การ์ด: มูลค่าทุนรวม · มูลค่าขายรวม · กำไรคงค้าง · จำนวนสินค้า
  • ตารางรายสินค้า เรียงมูลค่ามาก→น้อย ค้นชื่อ + กรองหมวดได้
  • คลิก "สต็อคสินค้า" → admin ลงแท็บนี้, พนักงานลง "ค้างสต็อก" (ไม่เห็นแท็บนี้)

4 ส่งผลอย่างไร

ข้อดี

  • เห็นมูลค่าเงินจมในสต็อก (ทุน/ราคาขาย/กำไรคงค้าง) ได้ในแท็บเดียว
  • ต่อยอดของเดิมล้วน ๆ — แพตเทิร์น table-card + setSummary + requirePermission ที่มีอยู่แล้ว ทำเร็ว กลมกลืน
  • ไม่แตะ schema / ไม่ migration / ไม่กระทบ flow อื่น (เพิ่ม IPC อ่านอย่างเดียว 1 ตัว)
  • ปลอดภัยด้านการเงิน — gate 3 ชั้น (ซ่อนแท็บ + redirect หน้า + requirePermission ฝั่ง main)

ข้อเสีย / ต้นทุน

  • เพิ่มไฟล์หน้าใหม่ 1 ไฟล์ + แตะ index/route/preload/reports รวม ~5 ไฟล์
  • ยอดรวมในแท็บนี้ จะไม่ตรงเป๊ะกับผลรวมแท็บ "ค้างสต็อก/ต่ำกว่าจุดสั่งซื้อ" เพราะแท็บนี้ตั้งใจรวมสินค้าปิดใช้งานที่ยังมีของด้วย (ดูข้อควรระวัง)

ข้อควรระวัง

  • Rules-of-Hooks: hook ทั้งหมดต้องอยู่เหนือ if(!canCost) return <Navigate/> เสมอ + ใส่ if(!canCost) return ในตัว effect (กันจอขาวตอนสลับ role)
  • สิทธิ์: gate ด้วย cost.view === 'allow' (ไม่ใช่ !== 'off') เพราะทั้งหน้าเป็นต้นทุน ถ้าไม่ allow IPC จะ throw ทั้งก้อน
  • มูลค่ารวม VAT: ทั้ง price_retail และ lot cost_price เก็บเป็น gross อยู่แล้ว — กำไร = ขาย − ทุน ไม่ต้อง strip VAT
  • div-by-zero: HAVING qty_on_hand > 0 เป็นตัวกัน "ทุน/หน่วย" หารศูนย์ — ห้ามถอด HAVING
  • ห้าม emoji ใน UI · ใช้ lucide icon + semantic token เท่านั้น · bar=h-12 control=h-9

5 UX / UI

  • ที่อยู่: การจัดการ › สต็อคสินค้า › มูลค่าคงคลัง (sub-tab แรกสุด, icon Coins)
  • การ์ดสรุป (setSummary): มูลค่าทุนรวม (tint primary) · มูลค่าขายรวม (info-soft) · กำไรคงค้าง (success) · จำนวนสินค้า (secondary)
  • ตาราง 7 คอลัมน์: สินค้า · หมวด · คงเหลือ · ทุน/หน่วย (weighted) · มูลค่าทุน · มูลค่าขาย · จัดการ(ปุ่มดู Eye → หน้าแก้สินค้า) — เรียงเริ่มต้นที่ "มูลค่าทุน" มาก→น้อย, sortable
  • filter strip: ชื่อหัวตาราง + Badge จำนวน + SearchInput ค้นชื่อ + ปุ่ม Popover กรองหมวด (มี "ไม่มีหมวด", ลิสต์ยาว scroll ได้)
  • status bar ล่าง: "แสดง N รายการ" + มูลค่าทุนรวม + มูลค่าขายรวม
  • บทบาท: เจ้าของ/เภสัช (cost.view=allow) เห็นและใช้ได้ · พนักงาน (off) ไม่เห็นแท็บ และเปิด URL ตรงก็ถูก redirect
  • ภาษาไทยทั้งหมด · เงิน ฿{formatCurrency()} · ไม่มีหน้าจอ staff เปลี่ยนแปลง

    STEP 1 — IPC handler in electron/ipc/reports.ts (inside registerReportHandlers()): 
    ipcMain.handle('reports:inventoryValuation', (_e) => {
  requirePermission(_e, 'cost.view')   // throws FORBIDDEN for non-allow
  const db = getDb()
  return db.prepare(`
    SELECT p.id AS product_id, p.trade_name,
           COALESCE(c.name,'ไม่มีหมวด') AS category_name, p.category_id,
           u.name AS unit_name,
           COALESCE(SUM(pl.qty_on_hand),0)               AS qty_on_hand,
           COALESCE(SUM(pl.qty_on_hand*pl.cost_price),0) AS cost_value,
           COALESCE(SUM(pl.qty_on_hand),0)*p.price_retail AS retail_value
    FROM products p
    JOIN product_lots pl ON pl.product_id = p.id AND pl.is_closed = 0
    LEFT JOIN product_categories c ON c.id = p.category_id
    LEFT JOIN item_units u ON u.id = p.unit_id
    WHERE p.is_bundle = 0
    GROUP BY p.id HAVING qty_on_hand > 0
    ORDER BY cost_value DESC
  `).all()
})
