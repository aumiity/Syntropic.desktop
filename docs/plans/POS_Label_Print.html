1 ภาพรวม — ทำอะไร ทำไม

ปัญหา: ปุ่ม "พิมพ์ฉลาก" ในหน้า POS ยัง disabled ใช้ไม่ได้ และระบบฉลากปัจจุบัน "พิมพ์ออกมาเป็นไทยล้วน" (composeLabelContent fix name_th/indication_th) ทั้งที่ DB เก็บคำแปลไว้หลายภาษาอยู่แล้ว

แผนนี้แก้ 2 เรื่องพร้อมกัน:

  • (A) นำระบบพิมพ์ฉลากเข้าหน้า POS — กดปุ่มแล้วเปิดหน้าต่างเลือกพิมพ์ฉลากของสินค้าในตะกร้า (ติ๊กอัตโนมัติ + เลือกฉลาก + จำนวนสำเนา) มีสวิตช์ดูสินค้าที่ยังไม่มีฉลาก + quick add
  • (B) รองรับ 4 ภาษา — เลือกภาษาได้ครั้งเดียวใช้ทั้งบิล (ไทย/English/พม่า/จีน) ฉลากจะดึงคำแปลตามภาษาที่เลือก โดย fallback กลับไทยเมื่อช่องนั้นยังว่าง

สถานะ 4 ภาษาใน DB ตอนนี้: ตาราง lookup ทั้ง 5 (ขนาดยา/ความถี่/มื้อ/เวลา/คำแนะนำ) มี name_th/en/mm/zh ครบ + seed แปลครบแล้ว เหลือแค่ สรรพคุณรายสินค้า (indication) ขาด English → แผนนี้เพิ่มคอลัมน์ indication_en ให้ครบ และเพิ่มช่องกรอกในฟอร์ม ส่วนฟอนต์พม่า/จีนยังไม่มีในแอป → bundle Noto เพิ่ม กันพิมพ์ออกมาเป็นกล่อง (tofu)

3 ก่อน ↔ หลัง

ก่อน

  • ปุ่ม "พิมพ์ฉลาก" ในหน้า POS กดไม่ได้ (disabled ถาวร)
  • ฉลากพิมพ์เป็นไทยล้วนเสมอ — สลับภาษาไม่ได้แม้ DB เก็บคำแปลไว้
  • สรรพคุณรายสินค้าขาดช่อง English (มีแค่ ไทย/พม่า/จีน)
  • ไม่มีฟอนต์พม่า/จีนในแอป → ถ้าพิมพ์ออกมาจะเป็นกล่อง

หลัง

  • ปุ่มเปิดใช้ได้เมื่อมีของในตะกร้า → หน้าต่างพิมพ์ฉลาก
  • เลือกภาษาครั้งเดียวใช้ทั้งบิล — ฉลากดึงคำแปลตามภาษา (fallback ไทย)
  • กรอกสรรพคุณได้ครบ 4 ภาษาในฟอร์มเดียว
  • พม่า/จีน render ชัดด้วย Noto ที่ฝังเฉพาะเมื่อมีอักษรนั้น (Thai-only ไม่อืด)

4 ส่งผลอย่างไร

ข้อดี

  • พิมพ์ฉลากหลายภาษาจากหน้าขายได้ทันที — ตรงกับลูกค้าพม่า/จีนของร้าน
  • ใช้คำแปล lookup ที่ seed ไว้ครบอยู่แล้ว — แค่ปลดล็อกให้เลือกภาษา
  • แตะ schema น้อยมาก (+1 คอลัมน์ ผ่าน migration ที่ปลอดภัยกับ DB เดิม)
  • ฝังฟอนต์ตามเนื้อหา — บิลไทยล้วนไฟล์เล็กเท่าเดิม จ่ายต้นทุน CJK เฉพาะตอนใช้
  • ฟอร์มฉลากแยกเป็น component ร่วม (SSOT) ใช้ทั้งหน้าสินค้าและ POS

ข้อเสีย / ต้นทุน

  • เพิ่มไฟล์ฟอนต์ในรีโป — Noto Sans SC (จีน) ราวหลาย MB (Myanmar เล็ก) → repo + ไฟล์พิมพ์ตอนมีจีนใหญ่ขึ้น (อนาคต subset ได้)
  • แตะ schema/IPC แล้ว — ไม่ใช่งาน UI ล้วนเหมือนแผนเดิม จึงต้อง migrate + ทดสอบ DB เดิม
  • composeLabelContent เปลี่ยน signature → กระทบ LabelsTab 2 จุดเรียก (ต้องอัปเดต)
  • ฝังฟอนต์ 2 น้ำหนัก (Regular+Bold) ต่อภาษาที่ใช้ → ไฟล์พิมพ์ตอนมี CJK ใหญ่ขึ้นอีกเท่าตัว (แต่ได้ bold จริง)

ข้อควรระวัง (invariant)

  • saveLabel named-param subset เป๊ะ — เพิ่ม indication_en ต้องใส่ทั้งใน payload object และใน INSERT column list/VALUES พร้อมกัน ไม่งั้น throw "Too many parameter values" (ดู project_drug_label.md)
  • migration ปลอดภัยกับ DB เดิม — ใส่ ALTER ใน array ที่ห่อ try{}catch{} (schema.ts:765) เท่านั้น; เพิ่ม indication_en ใน CREATE TABLE สำหรับ DB ใหม่ด้วย
  • fallback ภาษา — ช่องที่ภาษาเลือกว่าง ต้องถอยกลับ *_th (name_th NOT NULL การันตีไทยมีเสมอ) ไม่ใช่ปล่อยว่าง
  • composeLabelContent default lang='th' — ค่าเริ่มต้นต้องให้ผลเท่าเดิมเป๊ะ (กัน LabelsTab/Settings designer เพี้ยน)
  • render path 1:1 — แถวพิเศษ shop+วันที่ และ shop_phone+barcode คงตรรกะเดิมทั้งคู่
  • ฝังฟอนต์ตามอักษรจริง — สแกน content; มีพม่า→ฝัง Myanmar, มี CJK→ฝัง SC; ต่อ family เข้า stack ก่อน sans-serif
  • ห้าม coerce ค่าว่าง→0 (จำนวนสำเนา clamp 1..99) · Select คืน string (แปลง Number ทุกครั้ง) · show_barcode รายฉลากทับ global · โฟกัส POS (เพิ่มใน anyModalOpen + refocusSearch)
