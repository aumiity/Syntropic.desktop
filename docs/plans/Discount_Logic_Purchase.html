ส่วนลดการรับสินค้า — ยุบเหลือ row.discount ก้อนเดียว

ลบส่วนลดท้ายบิลที่ซ่อนอยู่ (bill_discount) — เหลือส่วนลดต่อแถวก้อนเดียว, ปุ่มท้ายบิลกลายเป็นเครื่องมือกระจายส่วนลดตามสัดส่วน

ผ่าน audit 2 รอบ ขอบเขต: GR receive (Purchase) 2026-06-24

1 ภาพรวม — ทำอะไร ทำไม

ปัญหาเดิม: หน้ารับสินค้ามีส่วนลด 2 ก้อนซ่อนอยู่ในคอลัมน์เดียว — ส่วนลดสินค้า (row.discount) กับ ส่วนลดท้ายบิลที่กระจายลงแถว (bill_discount) คอลัมน์โชว์ผลรวมของทั้งคู่ พอผู้ใช้กด "ล้างส่วนลด" ของแถว ช่องกลับไม่เป็น 0 เพราะยังมีท้ายบิลเกาะอยู่ → สับสนมาก

แผนนี้แก้โดย: ยุบให้เหลือส่วนลดก้อนเดียวต่อแถว (row.discount) เท่านั้น ทิ้งฟิลด์ bill_discount และกลไกสำรอง (baseRowTotals, appliedDiscount) ออกหมด

  • แก้ส่วนลดรายตัว (คลิกที่คอลัมน์ส่วนลดของแถว) → กระทบแถวนั้นแถวเดียว กดล้าง = 0 จริง
  • ปุ่มส่วนลดท้ายบิล = เครื่องมือ "ตั้งยอดส่วนลดรวมทั้งบิล แล้วกระจายลงทุกแถวตามสัดส่วน qty×ทุน ใหม่ทั้งหมด" → เขียนผลลง row.discount ทันที จบเลย ไม่เก็บร่องรอย
  • มีคำเตือนใน modal ท้ายบิลว่าจะกระจายส่วนลดทั้งหมดใหม่ตามสัดส่วน กดตกลงเพื่อยืนยัน
  • บัญชี/สรุปท้ายตาราง = ผลรวม row.discount ก้อนเดียว

เสร็จแล้วได้: ทุกตัวเลขในตารางคูณ/ลบกันลงตัว ตรวจสอบเองได้ ไม่มี * ไม่มี tooltip ลับ ๆ และพฤติกรรม "กดล้าง = 0" ตรงสามัญสำนึก

3 ก่อน ↔ หลัง

ก่อน

  • 2 ฟิลด์: discount + bill_discount
  • คอลัมน์โชว์ ผลรวม + เครื่องหมาย * + tooltip "รายตัว X · ท้ายบิล Y"
  • กดล้างส่วนลดรายตัว → ช่องไม่เป็น 0 (ยังมี bill_discount)
  • เปิด modal รายตัวกดตกลงค่าเดิม → bill_discount โดนยุบรวม
  • กลไกสำรอง baseRowTotals / appliedDiscount ต้องดูแลตลอด
แถวเดียว gross 100, รายตัว 5, ท้ายบิล 10 คอลัมน์: "15 *" tooltip: รายตัว 5 · ท้ายบิล 10 ตั้งรายตัว = 0 → คอลัมน์ "10 *" (ไม่ใช่ 0)

หลัง

  • 1 ฟิลด์: discount เท่านั้น
  • คอลัมน์โชว์ row.discount ตรง ๆ ไม่มี * ไม่มี tooltip
  • กดล้างส่วนลดรายตัว → ช่องเป็น 0 จริง
  • ปุ่มท้ายบิล = กระจายตามสัดส่วนใหม่ทั้งหมด (มีคำเตือน)
  • ไม่มีกลไกสำรอง — อ่าน/เขียนที่เดียว
แถวเดียว gross 100 ตั้งรายตัว 5 → คอลัมน์ 5, total 95 ท้ายบิล: เห็น 5 → ตั้ง 15 → total 85, คอลัมน์ 15 ตั้งรายตัว = 0 → คอลัมน์ 0, total 100 ✓

4 ส่งผลอย่างไร

ข้อดี

  • พฤติกรรม "กดล้าง = 0" ตรงสามัญสำนึก — จบปัญหาความสับสนหลัก
  • ลดความซับซ้อนของโค้ดมาก: ลบ 1 ฟิลด์ + 2 state + helper + การ์ด tooltip ทิ้ง
  • ทุกตัวเลขในตารางตรวจสอบเองได้ (กระทบแถวเดียว = แถวเดียว)
  • ต้นทุน/ล็อต/รายงานไม่กระทบ — cost_price = total/qty เหมือนเดิม

ข้อเสีย / ต้นทุน

  • ส่วนลดท้ายบิลย้อนกลับแบบแยกก้อนไม่ได้อีก — มันยุบลง row.discount ทันที (เลิก reversible model เดิม)
  • ตั้งส่วนลดรายตัวเองหลายแถว แล้วไปแตะ modal ท้ายบิลทีหลัง → กระจายใหม่ทับของเดิมทั้งหมด (ตามที่เจ้าของยืนยัน + มีคำเตือน)

ข้อควรระวัง

  • การ fold draft เก่าต้องอยู่ใน lazy initializer ของ useState (บรรทัด 111) เท่านั้น ห้ามทำใน effect — ไม่งั้น persist effect เขียนทับก่อน ทำให้ bill_discount เก่าหาย/นับซ้ำ
  • อย่าแก้ discount-dialog.tsx — เป็น primitive ใช้ร่วมกับ POS เปลี่ยนแค่ props ที่ GR ส่งเข้าไป
  • บิลโมดัลต้องใช้ grossSubtotal ตัวเดียวกันทั้ง open/apply (อย่าสร้าง helper คู่ขนาน — กัน preview เพี้ยน)
  • blank→0 ban: เขียนแค่ discount/total ห้าม coerce cost_price/qty ที่ว่างเป็น 0; แถว w<=0 ข้ามไปเลย
  • ใช้ semantic token เท่านั้น (กล่องคำเตือน amber = bg-amber-soft/border-amber-strong)

5 UX / UI

  • คอลัมน์ "ส่วนลด" ในตาราง GR — ยังเป็นปุ่ม variant="destructive-soft" โชว์ row.discount ตรง ๆ (ตัด * + tooltip ออก); เปิดโหมด "รวมส่วนลดในต้นทุน" (mergeCost) → โชว์ "—" กดไม่ได้ เหมือนเดิม
  • modal ส่วนลดรายตัว = DiscountDialog เดิม (ใช้ร่วม POS) — % / บาท / ราคาสุดท้าย + preset; seed จาก row.discount
  • modal ส่วนลดท้ายบิล = เพิ่มกล่องคำเตือน amber + AlertTriangle ด้านบน: "ส่วนลดทั้งหมดจะถูกกระจายลงสินค้าตามสัดส่วนใหม่ทั้งหมด กดตกลงเพื่อยืนยัน" — ปุ่ม ตกลง = การยืนยัน; ช่องโชว์ยอดรวมส่วนลดปัจจุบัน
  • สรุปท้ายตาราง — บรรทัดเดียว: ราคารวมก่อนลด / ส่วนลด / มูลค่ารวมทั้งหมด (ไม่ต้องแยกสินค้า/ท้ายบิลแล้ว)
  • ทุกอย่างคุม token + กฏ bar=h-12 / control=h-9 เดิม ไม่แตะความสูง
