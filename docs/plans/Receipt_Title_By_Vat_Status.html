หัวกระดาษใบเสร็จกำหนดตามสถานะ VAT/NoVAT ของบิล

ใบเสร็จในแอป (POS + ประวัติการขาย) ให้หัวกระดาษขึ้นกับว่าบิลนั้นมี VAT ไหม ไม่ใช่สวิตช์ตั้งค่าด้วยมืออีกต่อไป

ผ่าน audit 2 รอบ ขอบเขต: หัวกระดาษ slip (POS + Manage + SaleDetail + Settings preview) 2026-06-12

1 ภาพรวม — ทำอะไร ทำไม

ปัญหา: หัวกระดาษใบเสร็จในแอปขึ้นว่า "ใบเสร็จรับเงิน" เสมอ เพราะการเปลี่ยนเป็น "ใบกำกับภาษีอย่างย่อ" ถูกล็อกไว้หลังสวิตช์ตั้งค่าด้วยมือ (abbrev_tax_invoice — toggle "ใช้สลิปเป็นใบกำกับภาษีอย่างย่อ" ในแท็บตั้งค่าใบเสร็จ) ถ้าสวิตช์นี้ปิด หัวก็เป็น "ใบเสร็จรับเงิน" ตลอด แม้บิลจะมี VAT

สิ่งที่ควรเป็น: หัวกระดาษต้องสะท้อน "ความจริงของบิล" — บิลที่มี VAT (total_vat > 0) ต้องขึ้น "ใบกำกับภาษีอย่างย่อ" เสมอ ส่วนบิลที่ไม่มี VAT ขึ้น "ใบเสร็จรับเงิน" — โดยไม่ต้องมีใครมาตั้งค่าเอง

แผนนี้แก้โดย: ตัด gate ของสวิตช์ตั้งค่าทิ้ง แล้วให้หัวกระดาษขึ้นกับ sale.total_vat ของบิลล้วน ๆ, รวมตรรกะที่ซ้ำกัน 3 ที่ให้เป็นฟังก์ชันกลางตัวเดียว (resolveSlipMode), และลบสวิตช์ที่ไม่จำเป็นออกจากหน้าตั้งค่า

เสร็จแล้วได้: ร้านที่จด VAT พิมพ์บิลออกมาเป็นใบกำกับภาษีอย่างย่อโดยอัตโนมัติ, บิลที่พนักงานไม่ติ๊ก VAT (หรือร้านที่ไม่จด VAT) ยังเป็นใบเสร็จรับเงินถูกต้อง, บิลยกเลิก/รับคืนคงหัวเดิม

4 ส่งผลอย่างไร

ข้อดี

  • หัวกระดาษถูกต้องตามกฎหมายอัตโนมัติ — ร้านจด VAT ออกใบกำกับภาษีอย่างย่อโดยไม่ต้องตั้งค่า
  • บิลที่พนักงานไม่ติ๊ก VAT (total_vat=0) → เป็นใบเสร็จรับเงินถูกต้อง สอดคล้องกับที่บิลนั้นไม่เข้ารายงานภาษีขาย
  • ตรรกะรวมเป็นฟังก์ชันกลางตัวเดียว — กันการแก้ที่เดียวลืมอีก 2 ที่ (drift)
  • หน้าตั้งค่าใบเสร็จสะอาดขึ้น — ลบสวิตช์ที่ทำให้สับสน

ข้อเสีย / ต้นทุน

  • ไม่ใช่การเสียการควบคุม — ร้าน VAT ยังกำหนดได้ "ต่อบิล" ผ่าน checkbox VAT ใน payment dialog: ไม่ติ๊ก VAT → total_vat=0 → พิมพ์ "ใบเสร็จรับเงิน". ปุ่มควบคุมแค่ย้ายจาก toggle รวมทั้งร้าน → ต่อบิล (ถูกต้องกว่า เพราะหัวกระดาษผูกกับว่า "บิลนี้บันทึก VAT จริงไหม")
  • คอลัมน์ abbrev_tax_invoice ใน DB กลายเป็น dead column ชั่วคราว (คงไว้เฉย ๆ ไม่มี migration ตอนนี้) — จดไว้ มีแผนลบจริงในรอบปรับ schema ก่อน launch program จริง

ข้อควรระวัง

  • invariant ห้ามแตะ allow-list save payload — abbrev_tax_invoice ยังเป็นคอลัมน์จริง คงไว้ใน DEFAULTS ไม่ให้ dynamic UPDATE พัง
  • ข้อกฎหมาย: ใบกำกับภาษีอย่างย่อ ม.86/6 ปกติต้องได้รับอนุมัติจากสรรพากรก่อน — แผนนี้ถือว่าร้านที่จด VAT ในแอป = ได้รับอนุมัติแล้ว (ตามมติของพี่)
  • บิลเก่าที่เก็บไว้อ่าน total_vat snapshot ของตัวเอง การพิมพ์ซ้ำจึงตรงกับตอนขายเสมอ ไม่ขึ้นกับสถานะ VAT ปัจจุบันของร้าน

5 UX / UI

  • หน้า POS / ประวัติการขาย: ไม่มี UI ใหม่ — แค่หัวกระดาษบนสลิปที่พิมพ์เปลี่ยนตามบิล
  • หน้าตั้งค่าใบเสร็จ (ReceiptSettingsTab): ลบ Toggle "ใช้สลิปเป็นใบกำกับภาษีอย่างย่อ" ออก (คง Toggle "พิมพ์ใบเสร็จอัตโนมัติ" และกรอบกลุ่มสวิตช์เดิม) — ไม่เพิ่ม primitive ใหม่ ไม่มี raw HTML ไม่มีสี literal
  • หน้าตัวอย่าง (preview) ในตั้งค่าใบเสร็จ: เดิมขึ้นกับสวิตช์ → เปลี่ยนเป็นขึ้นกับสถานะร้าน VAT (useShopVat): ร้านจด VAT โชว์ "ใบกำกับภาษีอย่างย่อ" + บรรทัด VAT; ร้านไม่จด VAT โชว์ "ใบเสร็จรับเงิน" ไม่มีบรรทัด VAT
  • ภาษาไทยทั้งหมด, คงโทนตามแอป — งานนี้เป็นการ "ลบ + แก้ตรรกะ" ไม่ใช่เพิ่ม UI ใหม่

  • บิล VAT (total_vat > 0) พิมพ์หัว "ใบกำกับภาษีอย่างย่อ" โดยไม่มีสวิตช์ใดควบคุม

  • ทั้ง 3 จุดเรียก resolve mode ผ่าน resolveSlipMode ตัวเดียว
  • preview ในตั้งค่าใบเสร็จสะท้อนสถานะร้าน VAT
