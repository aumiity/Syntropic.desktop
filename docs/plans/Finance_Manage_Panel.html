1 ภาพรวม — ทำอะไร ทำไม

ปัญหา/โจทย์: หน้า การจัดการ › ประวัติการขาย ตอนนี้โชว์แค่ "การ์ดนับจำนวนบิล" ส่วนเงินกระจายอยู่ในแถวตาราง — แอดมินมองภาพการเงินรวมของช่วงเวลาไม่เห็นในหน้าเดียว ต้องเด้งไปหน้า Dashboard

แผนนี้ทำ: เพิ่ม ปุ่มพับ/กางแผง "ภาพรวมการเงิน" ในแถบเครื่องมือของหน้า Sales (เห็นเฉพาะ admin) กดแล้วกางแผงระหว่างแถบเครื่องมือกับตาราง โชว์การ์ด KPI (ยอดขายสุทธิ · ต้นทุนขาย · กำไรขั้นต้น · อัตรากำไร) พร้อมลูกศรเทียบช่วงก่อนหน้า และกราฟแนวโน้มยอดขาย/กำไร

เสร็จแล้วได้: แอดมินเห็นสุขภาพการเงินของช่วงวันที่ที่กำลังดูได้ทันทีในหน้าเดียว โดยพนักงาน (staff) ไม่เห็นปุ่มและไม่เห็นข้อมูลเลย — และ ไม่ต้องเขียน backend ใหม่ เพราะ reuse reports:financeSummary + reports:salesPurchaseTrend (ทั้งคู่ admin-only อยู่แล้ว) กับชุดกราฟ/การ์ดที่ Dashboard ใช้

ตัดสินใจที่ล็อกแล้ว (จากการสัมภาษณ์): ตัวเลขในแผง อิงช่วงวันที่อย่างเดียว (ตั้งใจ reuse ของเดิม) ไม่ผูกกับช่องค้นหา/ตัวกรองสถานะ/VAT ของตาราง · เริ่มทำ หน้า Sales ก่อน หน้าอื่น (Purchases / สต็อก) ค่อยขยายเฟสถัดไป

3 ก่อน ↔ หลัง

ก่อน

  • เหนือตาราง = การ์ดนับจำนวนบิลล้วน (จำนวนบิล/ปลีก/ส่ง/รับคืน/ยกเลิก)
  • เงินอยู่ในแถวตารางทีละบิล — ไม่มีภาพรวมการเงินของช่วง
  • แอดมินอยากดูกำไร/มาร์จิ้นรวมต้องไปหน้า Dashboard (ภาพรวมทั้งร้าน ไม่ใช่ช่วงที่กำลังกรอง)

หลัง

  • มีปุ่มไอคอน "ภาพรวมการเงิน" ในแถบเครื่องมือ (admin เท่านั้น) · ปิดเป็นค่าเริ่มต้น
  • กดแล้วกางแผง: KPI 4 ใบ + กราฟแนวโน้ม + โน้ตบอกขอบเขต
  • ตัวเลขสะท้อน ช่วงวันที่ที่เลือกอยู่ ทันที (Dashboard ทำไม่ได้) · พับเก็บได้ จำสถานะข้ามการสลับแท็บ
  • staff ไม่เห็นปุ่ม ไม่ยิง IPC เลย

4 ส่งผลอย่างไร

ข้อดี

  • ไม่แตะ backend เลย — reuse IPC + กราฟ + การ์ดเดิม ความเสี่ยงต่ำ งานอยู่ในไฟล์เดียว
  • ให้คุณค่าที่ Dashboard ให้ไม่ได้: ตัวเลขผูกกับ "ช่วงวันที่ที่กำลังดู" ไม่ใช่ภาพรวมทั้งร้าน
  • โหลดแบบ lazy (เฉพาะตอน admin เปิดแผง) — ไม่กระทบ perf ของการใช้งานปกติ/พนักงาน
  • เป็นต้นแบบที่ขยายไป Purchases / สต็อก ในเฟสถัดไปได้ทันที

ข้อเสีย / ต้นทุน

  • แผงกินพื้นที่แนวตั้งตอนกาง — ที่จอเล็กสุด 1440×800 ตารางจะเตี้ยลง (คุมด้วยกราฟสูง 180 + ปิดเป็นค่าเริ่มต้น)
  • ช่วงวันที่กว้างมาก (เช่น custom ทั้งปี) คิวรีต้นทุนต่อล็อตจะหนัก (ดู "ข้อควรระวัง")
  • ตัวเลขแผงอิงวันที่อย่างเดียว — อาจไม่ตรงกับยอดในตารางตอนกรองสถานะ/ค้นหา (จัดการด้วยโน้ต)

ข้อควรระวัง

  • บิลยกเลิก vs ตัวกรอง: financeSummary ตัดบิล voided ออกจากยอดขาย (reports.ts:458) แต่ตารางกรองเป็น "ยกเลิก" ได้ → ถ้าผู้ใช้กรองตารางเหลือเฉพาะบิลยกเลิก แผงจะโชว์ยอดขาย (ที่ไม่นับ voided) ขัดกับตาราง. กันด้วย โน้ต info-soft ที่ระบุชัดว่าแผงเป็น "ภาพรวมทั้งช่วง ไม่ขึ้นกับตัวกรอง และไม่นับบิลยกเลิก" — ทางเลือกถ้าพี่ต้องการ: ปิด/หรี่แผงเมื่อมีการกรอง (q/status/VAT) แทนการใช้โน้ต — ยังไม่ทำในเฟส 1 เว้นแต่พี่สั่ง
  • perf ช่วงกว้าง: ไม่เหมือน Dashboard (ที่จำกัดกราฟเป็นหน้าต่าง 7/30/90 วันถอยหลัง). แผงนี้รันทั้งช่วงที่เลือก + with_compare รัน window ซ้ำ 2 รอบ → ช่วงปีเต็มหนักกว่าที่ Dashboard เคยยิง. ยอมรับเพราะ lazy + ช่วงปกติคือวัน/เดือน
  • สิทธิ์: ปุ่ม + การ fetch ต้อง gate ด้วย isAdmin ทั้งคู่ (IPC ก็ requireAdmin ซ้ำอีกชั้น) — staff ห้ามยิงไม่งั้น throw
  • invariant: ปุ่มต้องเป็น ไอคอนล้วน h-9 w-9 ให้เข้ากับปุ่มอื่นในแถบ (ปุ่มมีป้ายความกว้างมากจะล้นแถบที่ 1440px) · token สีใช้ semantic เท่านั้น · ไม่มี emoji · ไอคอนใน Button ใช้ size-4
  • null guard: preload คืน any — ต้อง ?? null / ?? [] และรีเซ็ต trend ตอน error เลียนแบบ Dashboard

5 UX / UI

  • ปุ่ม toggle: ไอคอน LineChart อย่างเดียว size="lg" className="h-9 w-9 p-0" + tooltip="ภาพรวมการเงิน" วางต่อท้ายปุ่ม Settings2 ในแถบ h-12 · เปิดอยู่ = variant="default" (เขียว teal เด่น), ปิด = variant="elevated" เหมือนปุ่มพี่น้อง · เห็นเฉพาะ admin
  • แผง: กาง/พับด้วย AnimatePresence height (แพทเทิร์นเดียวกับ Manage/index.tsx) อยู่ใน card ระหว่างแถบเครื่องมือกับตาราง · เป็นแถบ border-b border-border p-4 ให้แยกขาดจากตาราง
  • KPI grid (grid-cols-2 md:grid-cols-4): ยอดขายสุทธิ (teal, +ลูกศร delta) · ต้นทุนขาย (amber) · กำไรขั้นต้น (success, +delta) · อัตรากำไร % (info-soft) — ทุกตัวเงินผ่าน formatCurrency
  • กราฟ: TrendChart สูง 180 โชว์เส้นยอดขาย+กำไร · มี GranularityTabs สลับหน่วยเวลา
  • โน้ตขอบเขต (info-soft): "ภาพรวมการเงินของทั้งช่วงวันที่ที่เลือก — รวมทุกบิลในช่วง ไม่ขึ้นกับช่องค้นหา / ตัวกรองสถานะ / VAT ด้านล่าง (บิลที่ยกเลิกไม่ถูกนับเป็นยอดขาย)"
  • สถานะ: กำลังโหลด → แถวจาง · ก่อนโหลดครั้งแรก → ไม่วาด · มีข้อมูลแต่ว่าง → "ไม่มีข้อมูลการขายในช่วงนี้"
  • ภาษาไทยทั้งหมด · อ้างแพทเทิร์น /theme + Dashboard เป็น SSOT ของหน้าตา

Definition of done

  • Toggle button "ภาพรวมการเงิน" (icon-only) shows in the Sales filter strip ONLY when isAdmin.
  • Click expands/collapses a panel between the filter strip and the table (animated height).
  • Open state persists via usePagePrefs (SalesPrefs.showFinancePanel, default false).
  • When open + admin: fetch reports.financeSummary({date_from, date_to, with_compare:true}) + reports.salesPurchaseTrend({date_from, date_to, granularity}) for the page's current date range.
  • KPI cards: ยอดขายสุทธิ (sales_net), ต้นทุนขาย (sales_cost), กำไรขั้นต้น (sales_profit), อัตรากำไร (profit/net %). net + profit carry a delta vs previous period.
  • TrendChart renders sales_net + sales_profit; GranularityTabs switches bucket size.
  • An info-soft note discloses date-only / filter-independent / voided-excluded scope.
  • Staff never trigger the admin IPC (button + fetch both gated by isAdmin).
  • Three render branches (loading / null / loaded) — no null-deref on finance.
  • npx tsc --noEmit passes; click-test in-app for admin + staff at 1440×800.
