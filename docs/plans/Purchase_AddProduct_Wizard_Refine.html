ขัดเกลา UI โมดัล "เพิ่มสินค้า" (AddProductWizard)

คง flow 4 ขั้นแบบ timeline เดิมไว้ทั้งหมด แต่ลดความ "อ้วน" จัดวางใหม่ให้กระชับ ตรงกฎ UI ของเรา ปรับจังหวะความสูง input ให้สม่ำเสมอ และทำให้ข้อมูล/การกรอกชัด-เร็วขึ้น

ผ่าน audit 2 รอบ (ไม่มี P0) ขอบเขต: AddProductWizard.tsx ไฟล์เดียว styling-only · ไม่แตะ logic/IPC 2026-06-12

1 ภาพรวม — ทำอะไร ทำไม

ปัญหา: โมดัลเพิ่มสินค้า (ไฟล์ src/pages/Purchase/AddProductWizard.tsx) ทำงานครบดี แต่หน้าตา "อ้วน" และจัดวางยังไม่ลงตัว — กรอบใหญ่ 4xl × h-[600px] ขณะที่บางขั้น (เช่นขั้น 2 มีแค่ Lot กับวันหมดอายุ) เหลือพื้นที่ว่างเยอะ, ตัวเลขความสูง input ปนกันไปหมด (h-10 / h-11 / h-14), แต่ละขั้นพิมพ์ "ขั้นที่ N" ซ้ำกับ timeline rail ที่บอกอยู่แล้ว, และช่องราคาขายขั้น 4 ปั้น border/เงา/ring เองด้วย className ดิบแทนที่จะใช้สไตล์มาตรฐาน (ผิดกฎ ELEVATED).

แผนนี้แก้: คงโครง 4 ขั้นเดิม แต่ (1) สลิม timeline rail + โชว์ไอคอนประจำขั้น, (2) ตัดหัวข้อ "ขั้นที่ N" ที่ซ้ำออก เหลือหัวข้อเดียวต่อขั้น, (3) ตั้งจังหวะความสูง input ใหม่ให้สม่ำเสมอ, (4) ลบ className ดิบของช่องราคา ให้ใช้ ELEVATED default, (5) บีบ padding/กรอบให้กระชับ. ไม่แตะ logic, state, การคำนวณ, IPC, หรือ payload ที่ส่งออกเลย — แก้แค่ JSX กับ className.

เสร็จแล้วได้: โมดัลที่ดูทันสมัย กระชับ ไม่โล่ง ตรงกฎ UI, จังหวะ input สม่ำเสมอ, ข้อมูลในแต่ละขั้นชัดขึ้น และตา flow เดิมที่ผู้ใช้คุ้นอยู่แล้ว.

3 ก่อน ↔ หลัง

ก่อน

  • กรอบ size="4xl" h-[600px] — กว้าง/สูงเกิน ดูโล่ง
  • Rail กว้าง w-60, วงกลม size-8, padding p-5 — เทอะทะ; ไอคอนประจำขั้นมีแต่ไม่ได้ใช้
  • แต่ละขั้นขึ้นต้นด้วย ขั้นที่ N + หัวข้อ text-xl — ซ้ำกับ rail
  • ความสูง input ปนกัน: ค้นหา h-10, Lot/วันที่ h-11, ตัวเลข h-14 text-2xl
  • ช่องราคาขายขั้น 4 ปั้น bg-card border shadow-sm focus:ring-2 ... เองด้วย className ดิบ — ผิดกฎ ELEVATED
  • ปุ่ม footer size="lg"

หลัง

  • กรอบ size="3xl" h-[560px] — กระชับ เต็มขึ้น (มี click-test gate เผื่อถอยกลับ 4xl)
  • Rail w-52 p-4, วงกลม size-7 โชว์ไอคอนประจำขั้นที่ active (number=ค้าง, Check=เสร็จ)
  • ตัด ขั้นที่ N ที่ซ้ำออก เหลือหัวข้อเดียว text-lg ต่อขั้น (ขั้น 4 คงคำว่า "ขั้นสุดท้าย" แบบกระชับ)
  • จังหวะสม่ำเสมอ: ช่องข้อความ h-10, ช่องตัวเลขเด่น h-12 text-xl
  • ช่องราคาขายใช้ ELEVATED default (className เหลือแค่ขนาด/ฟอนต์/text-center)
  • ปุ่ม footer คง size="lg" (ไม่เปลี่ยนเป็น xl — xl คือ px-10 สำหรับปุ่มข้อความล้วน)

4 ส่งผลอย่างไร

ข้อดี

  • หน้าตากระชับ ทันสมัย ไม่โล่ง — ตรงกับที่พี่อยากได้
  • ตรงกฎ UI: ลบ className ดิบของ input, ใช้ semantic token, ใช้ ELEVATED default
  • จังหวะความสูง input สม่ำเสมอ อ่านง่ายขึ้น
  • ความเสี่ยงต่ำมาก — แก้แค่ JSX/className ไฟล์เดียว ไม่แตะ logic; มี backup index.rowmode.bak.tsx อยู่แล้ว

ข้อเสีย / ต้นทุน

  • การแคบกรอบเหลือ 3xl ทำให้ขั้น 3 (กล่องตัวเลข 3 ช่อง) แคบลง — ต้อง click-test ยืนยันว่าไม่ตก/ไม่ล้น ก่อน commit (มี fallback กลับ 4xl)
  • ช่องราคาขัั้น 4 focus ring เปลี่ยนจาก teal 2px → ring-ring 1px (token มาตรฐานบ้าน) — เป็นการเปลี่ยน visual ที่ตั้งใจ
  • doc ui-theming.md:141 ระบุ DateInput default = h-10/bg-input ซึ่ง stale (จริงคือ h-9/elevated) — ควรแก้ doc เป็น follow-up

ข้อควรระวัง

  • Modal contract (HARD): ห้ามแตะ onClose/handler ที่ทำให้คลิกนอกแล้วปิด — บังคับใน dialog.tsx อยู่แล้ว, แค่อย่าใส่ handler ใหม่ทับ. Enter เดินหน้า/ยืนยัน, Esc ปิด — ต้องยังทำงาน
  • Dialog height ต้อง fixed (HARD rule 5a): คง h-[560px] ไว้ ห้ามปล่อย auto
  • ความสูง input h-10/h-12 เป็นข้อยกเว้นตั้งใจของ dialog form (ไม่ใช่กฎ bar=h-12/control=h-9 ซึ่งใช้กับ table-card bar เท่านั้น) — อ้างอิงโมดัล price/bill-adjust บนหน้าเดียวกันที่ใช้ h-9/h-10/h-12 อยู่แล้ว
  • วงกลม rail เล็กลงเป็น size-7 — ต้องเลื่อนเส้นเชื่อม left-[15px]→left-[13px] และ top-8→top-7 ให้ centre/flush
  • ห้ามใส่ emoji, ห้าม palette literal, ใช้ bracket syntax v3, ห้ามเล็กกว่า text-xs

5 UX / UI

โครงยังเป็น timeline rail ซ้าย + แพเนลเนื้อหาขวา ตาม /theme Modal Layout เดิม. การเปลี่ยนทั้งหมดเป็นเชิงสไตล์:

  • Rail: แคบลง วงกลมเล็กลง โชว์ไอคอน lucide ของขั้นที่ active — ให้ "อ่านสถานะ" ได้เร็วโดยไม่กินที่
  • หัวข้อแพเนล: เหลือบรรทัดเดียว text-lg font-bold ต่อขั้น (title role ≥ text-base ตามกฎ); ขั้น 4 ยังบอก "ขั้นสุดท้าย"
  • Input: ข้อความ h-10, ตัวเลขเด่น (จำนวน/ต้นทุน/รวม/ราคาขาย) h-12 text-xl ทุกช่องพึ่ง ELEVATED default (bg-card+border+shadow+ring) ไม่ปั้นเอง
  • ปุ่ม footer: ย้อนกลับ = elevated (secondary), ถัดไป = default (primary teal), ยืนยัน = success (เขียว สื่อจบงาน) — คง size="lg"
  • สี: semantic token ล้วน (primary/primary-soft/success/destructive/foreground-subtle...); chip หน่วยที่เลือก = primary-soft + ring-1 ring-primary
  • ภาษาไทยทั้งหมด น้ำเสียงเดิม; ไม่มี emoji, ใช้ lucide icon

    4. ยืนยันที่ 3xl/560px ว่าขั้น 3 (กล่องตัวเลข 3 ช่อง) และขั้น 4 ไม่ตก/ไม่ล้น/ไม่ scroll แปลก — ถ้าแน่นเกิน fallback กรอบกลับ size="4xl" (และ/หรือ h-[600px])
    5. ช่องราคาขั้น 4 ดูเป็น elevated (มี border+เงา+ring ตอน focus), แก้ได้, กำไร/มาร์จิ้นคำนวณถูก
    6. กดยืนยัน → แถวเข้า GR table เหมือนเดิมทุก field; แก้ไขแถวเดิม → wizard pre-fill + อัปเดตแถวเดิม
    7. Esc ปิดได้; คลิกนอกโมดัล ไม่ ปิด
