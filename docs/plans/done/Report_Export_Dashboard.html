ศูนย์รวมรายงาน/ส่งออก แบบการ์ด

ยกเครื่องแท็บ "ส่งออก" ใน /reports ให้เป็นแดชบอร์ดการ์ดจัดกลุ่มตามหมวด — แต่ละการ์ดมีตัวเลขสรุป + ปุ่ม Export Excel; ถอดปุ่มส่งออกออกจากหน้า Manage 5 หน้า

ผ่าน audit 2 รอบ 6 ชุดข้อมูลเดิม · ไม่แตะ backend 2026-06-25

1 ภาพรวม — ทำอะไร ทำไม

ปัญหา: ปุ่ม "ส่งออก Excel" กระจายอยู่ในหน้า การจัดการ หลายหน้า (Sales/Purchases/Expenses/Expiry/LowStock) ปนกับงาน operate/แก้ไข ทำให้รก และหน้าศูนย์รวม (/reports/export) เดิมเป็นแค่การ์ดเรียงยาว ๆ ปุ่มเดียว ดูแล้วจืด ไม่มีบริบท

แผนนี้แก้โดย: ยกเครื่องเนื้อหาแท็บ ส่งออก (ไฟล์ ExportHub.tsx) ให้เป็น "แดชบอร์ดรายงานแบบการ์ด" จัดกลุ่มตามหมวดสไตล์ Hygeia (การขาย / การซื้อ / บัญชี-ภาษี / สต็อก) แต่ละรายงาน = การ์ด 1 ใบที่มี ตัวเลขสรุป (เช่น ยอดขายรวม + จำนวนบิล) แล้วมีปุ่ม Export Excel ในการ์ด — แล้วถอดปุ่มส่งออกออกจากหน้า Manage ทั้ง 5 หน้า

เสร็จแล้วได้: ที่เดียวจบสำหรับการส่งออก/ดูสรุปย่อ, หน้า Manage สะอาดขึ้น, และโครงการ์ดเป็น config array ที่เพิ่มรายงานใหม่ทีหลังได้ด้วยการเพิ่ม 1 entry (เมื่ออยากได้พรีวิว/พิมพ์สวยค่อยมาเติม) — รอบนี้ ไม่แตะ backend เลย (reuse IPC อ่าน + handler export เดิมทั้งหมด)

3 ก่อน ↔ หลัง

ก่อน

  • หน้า Manage 5 หน้า มีปุ่ม ExportButton (iconOnly) อยู่ใน filter strip
  • แท็บ ส่งออก = การ์ดเรียงแถวยาว 6 ใบ ปุ่มเดียวต่อใบ ไม่มีตัวเลข
  • แท็บ ส่งออก ซ่อนจาก staff; staff ส่งออก หมดอายุ/เหลือน้อย ผ่านปุ่มใน Manage
  • ทั้งหน้า ExportHub gate ด้วย isAdmin (staff เห็น "เฉพาะผู้ดูแล")

หลัง

  • หน้า Manage ไม่มีปุ่มส่งออกแล้ว (สะอาดขึ้น)
  • แท็บ ส่งออก = การ์ดจัดกลุ่ม 4 หมวด แต่ละการ์ดมีตัวเลขสรุปเด่น + ปุ่ม Export Excel
  • แท็บ ส่งออก เห็นได้ทุก role; staff เห็นเฉพาะหมวด "สต็อก" (2 การ์ด) → ยังส่งออก หมดอายุ/เหลือน้อย ได้เหมือนเดิม
  • เพิ่มรายงานใหม่ = เพิ่ม 1 entry ใน config array

4 ส่งผลอย่างไร

ข้อดี

  • ที่เดียวจบสำหรับส่งออก + เห็นตัวเลขสรุปย่อ ๆ ก่อนส่งออก
  • หน้า Manage โล่งขึ้น โฟกัสงาน operate
  • ไม่แตะ backend → ความเสี่ยงต่ำ, รีวิวง่าย
  • โครง config ขยายได้ตามวิสัยทัศน์ Hygeia โดยไม่ต้องรื้อ

ข้อเสีย / ต้นทุน

  • การ์ดต้องยิง IPC สรุปเพิ่ม (financeSummary + vatSummary สำหรับ admin) ตอนเปิดหน้า/เปลี่ยนวันที่ — เบามาก (aggregate 2 query)
  • products.lowStock รันคิวรีเต็มเพื่ออ่าน count ที่ handler คืนมาในผลลัพธ์ object (ยอมรับได้; รายการ low-stock ปกติไม่เยอะ)
  • หมวดที่มีการ์ดเดียว (การขาย/การซื้อ) จะดูโล่งช่วงแรก — แลกกับโครงที่ขยายได้

ข้อควรระวัง (invariant)

  • สิทธิ์ staff ส่งออก หมดอายุ/เหลือน้อย ต้องไม่หาย (เฟส 2 ของ Excel Export ตั้งใจให้ staff ทำได้) → ต้องเปิดแท็บ ส่งออก ให้ staff เห็น และโชว์หมวดสต็อกให้ staff
  • financeSummary + vatSummary ติด requireAdmin → ห้ามเรียกเมื่อ !isAdmin (จะ throw) — guard ด้วย isAdmin
  • No emojis / semantic tokens เท่านั้น / ใช้ primitive จาก components/ui (Card/CardFooter/ExportButton/TintIcon) — ห้าม raw HTML
  • ทุก bar = h-12, control ข้างใน = h-9 (MultiDatePicker บน TabStrip คงเดิม); ปุ่ม ExportButton เป็น h-9 อยู่แล้ว
  • เงินแสดงผ่าน formatCurrency() เสมอ (รวม VAT ตามกฏ display)

5 UX / UI

เลย์เอาต์: หน้าเดียวเลื่อนลงได้ (page-scroll เดิมของ Reports). บนแถบ TabStrip ด้านขวา = MultiDatePicker (admin เท่านั้น, default mode month) ขับตัวเลขการ์ดที่อิงวันที่ + args การ export.

กลุ่ม: แต่ละหมวดมีหัวข้อ (text-base font-semibold) + grid การ์ด (grid grid-cols-2 md:grid-cols-3 gap-3). render เฉพาะหมวดที่ !adminOnly || isAdmin.

การ์ด: ประกอบจาก primitive Card เดิม — CardHeader (CardTitle = ชื่อ + CardAction = TintIcon มุมขวา + CardDescription = คำอธิบายสั้น) / CardContent (ตัวเลขเด่น text-3xl font-bold + บรรทัด sub text-sm text-muted-foreground) / CardFooter (ปุ่ม ExportButton เต็มความกว้าง). อ้างอิง /theme ส่วน Cards.

สี (tint ตาม role ของข้อมูล): ขาย=primary, ซื้อ=info, ค่าใช้จ่าย=violet, VAT=success, หมดอายุ=warning/amber, เหลือน้อย=destructive. ใช้ semantic token ทั้งหมด.

สถานะ: ระหว่างโหลดตัวเลข (admin) แสดง — หรือ skeleton ในช่องตัวเลข; ถ้าโหลด summary ไม่สำเร็จ ปุ่มส่งออกยังกดได้ (ไม่ผูกกัน). staff ไม่เห็นข้อความ "เฉพาะผู้ดูแล" อีกต่อไป — เห็นหมวดสต็อกเลย.

ภาษาไทย: ป้ายทั้งหมดภาษาไทย; ปุ่มใช้ default label "ส่งออก Excel" ของ ExportButton.
