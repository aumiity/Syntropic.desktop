บันทึกอุณหภูมิ–ความชื้น

สมุดบันทึกอุณหภูมิ–ความชื้นภายในร้านตามมาตรฐาน GPP — แท็บย่อยที่ 4 ใน "รายงาน อย." คีย์เป็นกริดทั้งเดือน ซ่อนจุดวัดที่ไม่ใช้ได้ ไฮไลต์ค่าผิดเกณฑ์ และพิมพ์รายงานรายเดือน A4 แนวนอน

ผ่าน audit 2 รอบ · +ปุ่ม generate (เพิ่มทีหลัง) Phase 1 (กราฟ = Phase 2) 2026-06-19

1 ภาพรวม — ทำอะไร ทำไม

ปัญหา: ร้านยาคุณภาพ (GPP) ต้องบันทึกอุณหภูมิ–ความชื้นของพื้นที่เก็บยาเป็นประจำเพื่อให้ผู้ตรวจ อย. ดูได้ ปัจจุบันร้านจดในสมุดติดผนัง ไม่มีที่เก็บในระบบ และต้องคัดลอกมือเวลาทำรายงาน

แผนนี้ทำ: เพิ่มหน้า "บันทึกอุณหภูมิ–ความชื้น" เป็นแท็บย่อยที่ 4 ใน รายงาน อย. ต่อจาก ข.ย.๙/๑๐/๑๑ ประกอบด้วย 4 ส่วน — (1) กริดคีย์ทั้งเดือน คลิกช่องพิมพ์ค่า เซฟทีละช่องอัตโนมัติ (2) เติมค่าอัตโนมัติทั้งเดือน เผื่อลืมบันทึกหลายวัน กดเติมค่าสมจริง (อยู่ในเกณฑ์ GPP) ทีเดียวทั้งเดือน — ค่าเริ่มต้นเติม เฉพาะช่องที่ว่าง ไม่ทับค่าจริงที่บันทึกไว้ (3) ซ่อน/แสดงจุดวัด ร้านไหนไม่มีตู้เย็นหรือที่เก็บสำรองก็ยุบทิ้งได้ มีผลทั้งบนจอและตอนพิมพ์ (4) พิมพ์รายงานรายเดือน A4 แนวนอน ใช้กล่องพิมพ์ร่วม ReportPrintDialog ที่มีอยู่แล้ว

ต่างจาก ข.ย.๙/๑๐/๑๑ ตรงไหน: ข.ย. ดึงข้อมูลจากการซื้อ/ขายอัตโนมัติ (อ่านอย่างเดียว) แต่หน้านี้ต้อง กรอกมือ เพราะค่าวัดมาจากเทอร์โมมิเตอร์/ไฮโกรมิเตอร์ จึงต้องมีตารางใหม่ในฐานข้อมูลเพื่อเก็บค่า

เสร็จแล้วได้: ร้านบันทึกค่าในแอป เห็นทันทีว่าวันไหนค่าเกินเกณฑ์ (พื้นแดง) แล้วพิมพ์รายงานรายเดือนยื่นผู้ตรวจได้เลย

4 ส่งผลอย่างไร

ข้อดี

  • ครบเอกสาร GPP ในแอปเดียว ไม่ต้องคัดมือ ลดข้อผิดพลาด
  • เห็นค่าผิดเกณฑ์ทันที จัดการได้ก่อนผู้ตรวจมา
  • นำกลไกเดิมมาใช้ซ้ำ 100% (A4Sheet, ReportPrintDialog, printDomSheets, MultiDatePicker โหมด month) — ไม่สร้างของใหม่ที่ซ้ำซ้อน
  • ตารางใหม่ล้วน ไม่แตะ schema เดิม → ไม่มีผลกระทบกับการขาย/สต็อก/FEFO

ข้อเสีย / ต้นทุน

  • เพิ่ม 2 ตาราง (env_log, env_settings) + IPC ใหม่ 1 ไฟล์ + 1 namespace ใน preload
  • กริดคีย์เป็นงานใหม่ (cell input + autosave + ไฮไลต์) — ส่วนที่ใช้เวลามากสุด
  • กราฟเส้น (ที่ Hygeia มี) เลื่อนไป Phase 2 เพื่อคุมขอบเขต

ข้อควรระวัง (invariant)

  • ห้าม coerce ว่าง→0 — ช่องว่างต้องเป็น NULL (อย่าใช้ parseFloat('')||0) ตามกฏ stock/cost; ทั้งค่า 0 และว่าง = แสดงเป็นช่องว่าง
  • Allow-list payload — env:saveCell ต้องตรวจ field กับชุดคอลัมน์ที่อนุญาตก่อนต่อ SQL ไม่งั้น "no such column"
  • กริดคีย์ = spreadsheet → ใช้ table-fixed + w-[%] (ข้อยกเว้นใน ui-table-card) ไม่ใช่ min-w-
  • ทุก bar = h-12, control ข้างใน = h-9; ปุ่มบน sub-tab line (h-10) = h-10 ตาม KhorYor9
  • วันที่บนจอผ่าน formatDate() (DD/MM/YYYY ค.ศ.); บนแผ่น A4 ใช้วันที่ไทยแบบทางการได้ (carve-out เอกสารพิมพ์)
  • ไม่มี emoji / ใช้ semantic token (bg-destructive-soft ฯลฯ) ไม่ใช่ palette literal; ใช้ <Input>/<Checkbox> ไม่เขียน raw HTML
  • ค่าที่เติมอัตโนมัติเป็นค่าประมาณสังเคราะห์ ไม่ใช่ค่าที่วัดจริง — โหมด default จึงเติมเฉพาะช่องว่าง (ไม่ทับค่าจริง) และไม่เติมวันในอนาคต; โหมด "ทับของเดิม" ต้องเลือกเองอย่างตั้งใจ

Schema (paste into the top exec block of schema.ts)

CREATE TABLE IF NOT EXISTS env_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  log_date TEXT NOT NULL,            -- 'YYYY-MM-DD'
  period   INTEGER NOT NULL,         -- 1=เช้า 2=กลางวัน 3=เย็น
  store_temp REAL, store_humidity REAL,
  reserve_temp REAL, reserve_humidity REAL,
  fridge_temp REAL,
  note TEXT,
  recorded_by INTEGER REFERENCES users(id),
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  UNIQUE(log_date, period)
);
CREATE TABLE IF NOT EXISTS env_settings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  zone_reserve_enabled INTEGER NOT NULL DEFAULT 1,
  zone_fridge_enabled  INTEGER NOT NULL DEFAULT 1,
  store_temp_max       REAL NOT NULL DEFAULT 30,
  store_humidity_max   REAL NOT NULL DEFAULT 75,
  reserve_temp_max     REAL NOT NULL DEFAULT 30,
  reserve_humidity_max REAL NOT NULL DEFAULT 75,
  fridge_temp_min      REAL NOT NULL DEFAULT 2,
  fridge_temp_max      REAL NOT NULL DEFAULT 8,
  updated_at TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

IPC channels (electron/ipc/env.ts)

  • env:getMonth({ year, month }) → EnvLogRow[] for that month (WHERE log_date BETWEEN ? AND ?), all periods. Empty month → [] (tolerates a fresh DB). Ungated read.
  • env:saveCell({ log_date, period, field, value }) → upsert. ALLOW-LIST field against a fixed Set {store_temp, store_humidity, reserve_temp, reserve_humidity, fridge_temp, note}; reject anything else (throw). Branch by type: numeric fields → empty/NaN → NULL (never 0); note → trimmed text, empty → NULL (never run through parseFloat). INSERT INTO env_log(log_date,period,[field],recorded_by) VALUES(…) ON CONFLICT(log_date,period) DO UPDATE SET [field]=@value, updated_at=datetime('now','localtime') — set recorded_by on INSERT only (row's original recorder; later field edits don't flip attribution). uid = getSession(e.sender.id)?.userId ?? null (import getSession — there is NO getCurrentUserId). Ungated (staff record daily).
  • env:generateMonth({ year, month, mode }) → bulk auto-fill in ONE transaction. mode: 'fill-empty' (default — only NULL cells, preserves real entries) | 'all' (regenerate every cell). For each (day, period, ENABLED-zone field) produce an in-band realistic value from env_settings thresholds: store/reserve temp ∈ [max−5, max−1], humidity ∈ [max−15, max−3]; fridge ∈ [min+0.5, max−0.5]. Use a per-zone random-walk (value drifts ±0.5–1 from the previous reading, then clamp inside the band) so it reads natural, not white noise. Round temp to 1 decimal, humidity to integer. Cap at today for the current month (don't fabricate future days); past months fill fully. Never touch note. recorded_by = current user on INSERT. Returns the month's rows so the grid refreshes. Ungated (same operational class as saveCell). Build the column list from the same allow-list Set — never interpolate field names.
  • env:getSettings() → singleton (read-or-INSERT-DEFAULT — first call materializes the default GPP row, so the grid's first render always has zone flags + thresholds). Ungated read.
  • env:setZones({ zone_reserve_enabled, zone_fridge_enabled }) → update only the two zone flags. Ungated — operational layout pref driven by the on-page popover (documented carve-out, same rationale as settings:saveBarcodeStickerSettings, ipc-api.md:47 + the DEVIATION comment at settings.ts:666-670). Add a matching comment citing that precedent.
  • env:saveSettings(data) → thresholds upsert from the Settings tab. requireAdmin(e) (settings write). The {id, updated_at, ...rest} dynamic UPDATE is NOT itself an allow-list — it builds SQL from whatever keys arrive (a stray key → no such column). Two guards: (a) the Settings-tab renderer sends only real env_settings columns (the gate, mirrors saveDocumentSettings settings.ts:644-648), AND (b) intersect Object.keys(rest) with an explicit column Set in the handler before building SQL.

Risks + mitigations

  • Autosave races. Save per-cell on blur (not per keystroke); the upsert is idempotent on (log_date,period). Reflect server truth only after the promise resolves (optimistic value kept in local state until then).
  • "no such column". The field allow-list Set is the gate — never interpolate field into SQL without membership check.
  • Zone hide must reach print. Print render reads the SAME env_settings zone flags the grid uses — single source, so preview and grid can't diverge.
  • Real data. Two brand-new tables; zero reads/writes to sales/stock/lots → no FEFO/finance impact. Rollback = drop the tables + revert files; existing DBs untouched.
  • Gating split. env:setZones ungated (carve-out, documented) vs env:saveSettings admin — confirm both are intended before shipping (mirrors the barcode-sticker carve-out).
  • Generate overwrites. Default fill-empty never touches a non-NULL cell, so real measurements are safe; only the explicit all mode overwrites. One transaction → all-or-nothing. Generated values always sit inside the configured thresholds (never produce a red cell). Cap at today so the current month never shows future readings.
