วิธีใช้ยาแก้ได้เอง + preset วิธีกิน

เปิดให้ผู้ใช้จัดการรายการ "วิธีใช้ยา" (เพิ่ม/แก้/ลบแบบรู้ผลกระทบ) แล้วสร้าง preset ที่กดทีเดียวเซ็ตวิธีกินครบในฟอร์มฉลาก

ผ่าน audit 2 รอบ 2 เฟส (lookup → preset) 2026-06-10

1 ภาพรวม — ทำอะไร ทำไม

วันนี้รายการ "วิธีใช้ยา" บนฉลาก (ปริมาณยา / ความถี่ / เวลาเทียบมื้อ / เวลา / คำแนะนำ) มาจากชุดข้อมูลที่ seed มาให้ตายตัว แก้เองไม่ได้ และปุ่มลัด 1x1..1pc ในฟอร์มฉลากก็แค่เขียนข้อความลงช่อง "ชื่อฉลาก" เฉย ๆ ไม่ได้เซ็ตวิธีกินจริง

แผนนี้แก้ 2 อย่าง:

  • เฟส 1 — เปิดหน้าจัดการ "วิธีใช้ยา" ใน ตั้งค่า ให้เพิ่ม/แก้/ลบรายการเองได้ และเวลาลบรายการที่ยังถูกใช้อยู่ ระบบจะโชว์ทุกฉลาก/preset ที่กระทบ ให้แก้หรือย้ายก่อน ไม่ลบทิ้งแบบมืดบอด
  • เฟส 2 — เปลี่ยนปุ่มลัดเป็น preset จริง ที่ผู้ใช้สร้างเอง กดทีเดียวเซ็ตครบทั้ง 5 ช่องวิธีกิน + ชื่อฉลาก พร้อม seed ชุดตั้งต้น 1x1..1hs ให้ใช้ได้ทันที

เสร็จแล้ว: เภสัช/เจ้าของร้านปรับคำวิธีกินให้ตรงร้านตัวเองได้ และออกฉลากเร็วขึ้นด้วยการกด preset ครั้งเดียว

2 โครงสร้าง / แผนผัง

ตาราง lookup กับช่องในฟอร์ม (ของเดิม) + ตารางใหม่

ช่องในฟอร์มฉลากตาราง lookupFK ใน product_labels
ปริมาณยาlabel_dosagesdosage_id
ความถี่label_frequenciesfrequency_id
เวลาเทียบมื้ออาหารlabel_meal_relationstiming_id
เวลาที่รับประทานlabel_timeslabel_time_id
คำแนะนำlabel_advicesadvice_id
ใหม่ ชุด preset วิธีกินlabel_presetsอ้าง 5 FK ข้างบน + name

การไหลของข้อมูล — ลบ lookup ที่ยังถูกใช้ (renderer ↔ IPC ↔ DB)

เส้นส้ม = เขียน DB · reassignLabelLookup กวาดทั้ง product_labels และ label_presets ใน transaction เดียว · deleteLabelLookup ลบจริงเมื่ออ้างอิงเหลือ 0

3 ก่อน ↔ หลัง

ก่อน

  • วิธีใช้ยา = ชุด seed ตายตัว แก้เองไม่ได้ (มีแต่ list* handler)
  • ปุ่ม 1x1..1pc เขียนแค่ "ชื่อฉลาก" ไม่เซ็ตวิธีกิน
  • ไม่มีหน้าจัดการ ไม่มี preset

หลัง

  • แท็บ วิธีใช้ยา ใน ตั้งค่า — เพิ่ม/แก้/ลบ 5 รายการเองได้
  • ลบรายการที่ถูกใช้ → dialog โชว์ฉลาก/preset ที่กระทบ → แก้รายตัว/ย้ายทั้งหมด → ลบจริง
  • แท็บ preset วิธีใช้ + chip preset ในฟอร์ม กดทีเดียวเซ็ต 5 ช่อง + ชื่อ

4 ส่งผลอย่างไร

ข้อดี

  • ร้านปรับคำวิธีกินให้ตรงตัวเองได้ ไม่ติดชุด seed
  • ลบแบบ "รู้ผลกระทบ" — เห็นทุกฉลาก/preset ที่อ้างอิงก่อนตัดสินใจ ไม่มีข้อมูลหายเงียบ
  • ออกฉลากเร็วขึ้น กด preset ครั้งเดียวครบ 5 ช่อง
  • หลังบ้านเป็น handler generic ตัวเดียวคุม 5 ตาราง โค้ดน้อย ดูแลง่าย

ข้อเสีย / ต้นทุน

  • เพิ่ม 1 ตาราง (label_presets) + 7 IPC handler + 3 หน้า/ไดอะล็อกใหม่
  • flow ลบแบบมีผลกระทบเป็น UX ใหม่ (ไม่เคยมีในแอป) ต้อง click-test ละเอียด
  • ฐานข้อมูลจริง (Hygeia) ที่ seed ไปแล้วจะได้ preset ตั้งต้นผ่าน back-fill เท่านั้น (idempotent ตาม code)

ข้อควรระวัง

  • allow-list invariant — handler ต้องเอาชื่อตาราง/คอลัมน์จาก map LOOKUP_KINDS ตามคีย์ kind เท่านั้น ห้ามรับจาก payload และห้ามสร้าง SQL จาก Object.keys(form)
  • FK ใน SQLite ไม่ถูก enforce — reassign ต้องเช็คว่า toId อยู่ในตารางเดียวกัน กัน FK ค้าง
  • แก้ main process (schema/settings/seed) ต้อง restart Electron — vite hot-reload ไม่หยิบให้ (บทเรียนจากเคส upgradeToVat "no handler")
  • ฟอร์มใช้ id 0 = "ไม่เลือก" — applyPreset ต้องแปลง null→0, handleSaveLabel แปลง 0→null อยู่แล้ว

5 UX / UI

  • หน้าจัดการ — การ์ด + ตาราง ตามมาตรฐาน table-card (bar h-12 / control h-9); จัดการรายแถว = ปุ่ม "ตัวเลือก" (Popover MoreHorizontal) มีเมนู แก้ไข + ลบ (ลบ = text-destructive) — ไม่ใช่ปุ่มไอคอนเรียงกัน ตาม docs/claude/ui-table-card.md
  • ยืนยันลบ (ไม่มีใครใช้) — ConfirmDialog แบบ structured info-card ในช่อง content (ไม่ใช่ prose) ตามแพตเทิร์น feedback_confirm_dialog_content_pattern ปุ่ม primary = destructive
  • dialog "จัดการฉลาก" — หัวเรื่องบอกจำนวน, ตารางฉลาก/preset ที่กระทบ (Badge แยกชนิด), ปุ่ม "แก้ไขทั้งหมด" เหนือตาราง, "แก้ไข" รายแถว, ปุ่ม "ลบรายการนี้" (destructive) ที่ footer เปิดเมื่ออ้างอิงเหลือ 0
  • ฟอร์มฉลาก — chip preset (Button size="sm" variant="primary-soft") แทนปุ่มลัดเดิม; โหมด restrict (enable เฉพาะช่องที่มีปัญหา) ซ่อน chip; ทุกข้อความภาษาไทย ใช้ semantic token เท่านั้น ไม่มี emoji
  • แท็บใหม่ ใต้ "หมวดหมู่และประเภท": วิธีใช้ยา (icon Stethoscope) + preset วิธีใช้ (icon ListChecks)

Definition of done

  • แท็บ วิธีใช้ยา ใต้ หมวดหมู่และประเภท: สลับ 5 ชนิด, ตารางต่อชนิด, เพิ่ม/แก้ (name_th บังคับ, en/mm/zh ไม่บังคับ), code auto-gen ฝั่ง main
  • ลบ lookup ที่ไม่มีใครใช้ → structured ConfirmDialog → ลบ
  • ลบ lookup ที่ถูกใช้ → "จัดการฉลาก" โชว์ฉลาก+preset ทั้งหมด; แก้รายแถว (restrict ช่องเดียว) / แก้ไขทั้งหมด (reassign หรือ NULL ใน 1 transaction); "ลบรายการนี้" เปิดเมื่อ refs=0
  • แท็บ preset วิธีใช้: ตาราง + เพิ่ม/แก้/ลบ preset (ลบไม่มีเงื่อนไข)
  • ฟอร์มฉลาก: QUICK_LABEL_NAMES ถูกแทนด้วย chip preset จาก DB; คลิก → เซ็ต 5 ช่อง + label_name
  • seed starter preset 1x1/1x2/1x3/1x4/1pc/1hs idempotent ผ่าน code subquery
  • npx tsc --noEmit ผ่าน + click-test ครบ

  dosage:    { table:'label_dosages',        fk:'dosage_id',     prefix:'DOS' },
  frequency: { table:'label_frequencies',    fk:'frequency_id',  prefix:'FRQ' },
  meal:      { table:'label_meal_relations', fk:'timing_id',     prefix:'MEL' },
  time:      { table:'label_times',          fk:'label_time_id', prefix:'TIM' },
  advice:    { table:'label_advices',        fk:'advice_id',     prefix:'ADV' },
} as const
function lookupKind(k:string){ const x=(LOOKUP_KINDS as any)[k]; if(!x) throw new Error('ชนิด lookup ไม่ถูกต้อง'); return x }

จุดเสี่ยง + วิธีกัน

  • allow-list → table/fk จาก LOOKUP_KINDS เท่านั้น, save คอลัมน์ literal
  • Hygeia → ลบ/ย้ายแตะแค่ product_labels/label_presets, transaction เดียว; composeLabelContent (content.ts) ทน fk NULL → render ว่าง ไม่ crash
  • FK ไม่ enforce → reassign guard same-kind
  • main change → restart Electron
  • 0=unset → applyPreset null→0, save 0→null (เดิมมีอยู่)
  • auth asymmetry → per-row edit ใช้ products:saveLabel (ไม่ admin-gate) แต่ทั้ง flow อยู่ใน Settings admin area + staff แก้ใน POS ได้อยู่แล้ว = ยอมรับได้
