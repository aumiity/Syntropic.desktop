GR Print Preview — กล่องพรีวิวก่อนพิมพ์ใบรับสินค้า (เฟส 2)

เปลี่ยนการพิมพ์ใบรับสินค้า (GR) จาก "พิมพ์เงียบ" → กล่องพรีวิว A4 แนวตั้งแบบเดียวกับ ข.ย.9/10/11 ปรับจำนวนสำเนา + กำหนดหน้าได้ ไม่มีปุ่ม PDF

ผ่าน audit 2 รอบ (ไม่มี P0/P1) เฟส 2 · GR เท่านั้น (A4 portrait) 2026-06-19

1 ภาพรวม — ทำอะไร ทำไม

วันนี้ใบรับสินค้า (ใบ GR) พิมพ์เงียบทันที ตอนกดปุ่มเครื่องพิมพ์ใน PurchaseReceiptDialog — ผู้ใช้ไม่เห็นหน้าตาก่อน เลือกหน้า/จำนวนสำเนาตอนพิมพ์ไม่ได้.

แผนนี้ทำให้ปุ่มพิมพ์ เปิดกล่องพรีวิว A4 แนวตั้ง แบบเดียวกับรายงาน ข.ย.9/10/11 — ซูมดูทีละหน้า, ใส่ "กำหนดหน้า" + "จำนวนชุด" ได้, และ สิ่งที่เห็นบนจอ = สิ่งที่พิมพ์ออกมา 1:1 (สำคัญมากเพราะใบ GR หลายหน้าบ่อย เช่น 30 รายการ).

ใช้กลไกพิมพ์ ตัวเดียวกับ ข.ย. (React A4Sheet + printDomSheets) โดย generalize ให้รองรับ "แนวตั้ง" — เพราะ ข.ย. เป็นแนวนอน แต่ GR เป็นแนวตั้ง. ตอนนี้ printDomSheets ฮาร์ดโค้ดแนวนอนล้วน.

3 ก่อน ↔ หลัง

ก่อน

  • กดปุ่มพิมพ์ใน PurchaseReceiptDialog → พิมพ์เงียบทันที (ไม่มีพรีวิว)
  • เลือกหน้า / จำนวนสำเนา ตอนพิมพ์ ไม่ได้
  • หลายหน้า: ไม่เห็นรอยตัดหน้าก่อนพิมพ์
  • เรนเดอร์ผ่าน buildGoodsReceiptHtml (HTML string) → printHtml

หลัง

  • กดปุ่มพิมพ์ → กล่องพรีวิว A4 แนวตั้ง (ซูมได้ พลิกหน้าได้)
  • ช่อง "กำหนดหน้า" + "จำนวนชุด" ใช้ได้จริง
  • เห็นบนจอ = พิมพ์ออกมา 1:1 ทุกหน้า
  • เรนเดอร์เป็น React A4Sheet → printDomSheets (กลไกเดียวกับ ข.ย.)
  • ไม่มีปุ่ม "ดูตัวอย่าง PDF"

หน้าตาแต่ละแผ่น: หัวร้าน + กล่องคู่ค้า (ทุกหน้า) → ตารางรายการ (ไหลต่อ) → ยอดรวมเงิน (ใต้ตาราง, หน้าสุดท้ายเท่านั้น) → พื้นที่ว่างเปล่าไม่มีเส้น → ลายเซ็น (ทุกหน้า ติดล่างสุด) → "หน้า X / Y".

4 ส่งผลอย่างไร

ข้อดี

  • WYSIWYG หลายหน้า — เห็นรอยตัดหน้าจริง ตรงกับที่พิมพ์ (จุดตายของ iframe ที่เราเลี่ยง)
  • กำหนดหน้าแม่นยำ — เลือกแผ่น DOM ฝั่ง client ไม่พึ่งการตัดหน้าที่มองไม่เห็น
  • กลไกเดียวทั้งระบบ — GR ใช้ท่อเดียวกับ ข.ย. (และต่อยอดใบกำกับภาษีในเฟส 3 ได้)
  • ปรับจำนวนสำเนาได้ + reuse ReportPrintDialog ที่พิสูจน์แล้ว

ข้อเสีย / ต้นทุน

  • ต้องเขียน layout ใบ GR เป็น React ใหม่ (1 ไฟล์ใหม่ + แก้ primitive ที่ใช้ร่วม 3 ไฟล์)
  • หน้าตาเทียบ HTML เดิมเป็น "ใกล้เคียง" ไม่ pixel-identical (ต้องจูน border/ระยะ)
  • qty เปลี่ยนจาก "5.00" → "5" (ตั้งใจ ไม่ใช่ regression)

ข้อควรระวัง

  • แตะ primitive ที่ ข.ย. + EnvLog ใช้ร่วม (A4Sheet/ReportPrintDialog/printDomSheets) → orientation ต้อง default เป็น 'landscape' เสมอ เพื่อให้ผู้เรียกเดิม (KhorYor9, KhorYorSaleLedger, EnvLog) ไม่เปลี่ยน — แล้ว regression test ทั้ง 4 จุด
  • ยอดรวมหน้าสุดท้าย = pack เป็น "pseudo-row ต่อท้าย" ด้วย budget เดียว → ไม่มีทางถูก overflow-hidden ตัด
  • วันที่ = formatDate(x, 'D MMMM BBBB') (พ.ศ. ทางการ ตาม carve-out เอกสารพิมพ์) + ต้องอัปเดต ui-theming.md:61 เพราะลบ buildGoodsReceiptHtml
  • ย้าย type ก่อนลบไฟล์ — GoodsReceiptForPrint/GoodsReceiptLine ย้ายเข้า component ใหม่ก่อน แล้วค่อยลบ builder + 2 ฟังก์ชัน (tsc gate)
  • infinite-loop ของ measure-pack → ผูก useLayoutEffect กับ array ที่ memo เสถียร ไม่ใช่ array ที่ derive ใหม่ทุก render

5 UX / UI

  • กล่องพรีวิว = ReportPrintDialog ตัวเดิม (ขนาด full, h-[88vh]) แต่ portrait — พื้นที่พรีวิวเลื่อนแนวตั้งได้, มี ZoomControl ลอยมุมขวาบน, ปุ่มพลิกหน้า "หน้า X / Y" ตรงกลาง.
  • แถบล่าง (DialogFooter): ช่อง "หน้า" (placeholder ทุกหน้า (1-N)) + ช่อง "จำนวนชุด" (number, min 1) ทางซ้าย; ปุ่ม ยกเลิก (variant="elevated" = secondary) + พิมพ์ (variant="default" = teal CTA หลัก) ทางขวา — ตามกฎปุ่ม dialog 2 ปุ่ม.
  • หัวกล่อง: "พิมพ์ใบรับสินค้า".
  • สี/โทเคน: แผ่นกระดาษใช้ semantic token (border-foreground/text-foreground/bg-card) เหมือน KhorYor9 ไม่ใช้ palette literal; ฟอนต์พิมพ์ = Sarabun Print (บังคับใน printDomSheets).
  • ภาษาไทยทั้งหมด; ไม่มี emoji; วันที่ในเอกสาร = พ.ศ. ทางการ (carve-out เอกสารพิมพ์).
  • ไม่มีปุ่ม PDF ในทุกจุดของ flow นี้.
