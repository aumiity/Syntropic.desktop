แบบที่เลือก: กรอบ + เรขาคณิตแถวคงเดิม (rounded-lg border + divide-y, แถว px-3 py-2.5, title+subtitle 2 บรรทัด) แต่ ย้าย checkbox มานำหน้าทางซ้าย คำอธิบายตามทางขวา → สื่อ "ติ๊กเลือกก่อนเซฟ" ชัดสุด + สแกนคอลัมน์กล่องซ้ายได้; เปลี่ยนจาก justify-between เป็น gap-3 (control ก่อน เนื้อหาตาม); ครอบทั้งแถวด้วย <label> → คลิกทั้งแถว; แถว destructive ยัง tint bg-destructive-soft/40 ตอนติ๊กเหมือนเดิม

Disclosure (เช่น "การแจ้งเตือนลูกค้า") — ติ๊กแล้วเผยช่องย่อย

การแจ้งเตือนลูกค้า
การ "เผยช่องย่อยทันที" เป็นแค่ UX ของ UI — ค่าที่เซฟยังรอปุ่มบันทึก จึงจัดเป็น checkbox ตามเกณฑ์ (ใช้กับ has_tax_invoice, is_alert)  ·  ข้อยกเว้น is_drug เจ้าของขอคงเป็น Switch

โค้ดที่จะเขียนจริง (แบบ A)

แถวในกรอบ grouped (มี title + subtitle) — <Checkbox> นำหน้าซ้าย คำอธิบายตามขวา ครอบแถวด้วย <label>:

<div className="rounded-lg border border-border divide-y divide-border overflow-hidden">
  <label className={`flex items-center gap-3 px-3 py-2.5
                      cursor-pointer select-none ${form.is_disabled ? 'bg-destructive-soft/40' : ''}`}>
    <Checkbox checked={!!form.is_disabled}
              onCheckedChange={v => setF('is_disabled', v ? 1 : 0)} />
    <div>
      <div className="text-sm font-semibold text-foreground">ปิดใช้งาน</div>
      <div className="text-xs text-muted-foreground">ปิดการใช้งานทั้งสินค้า</div>
    </div>
  </label>
</div>

กรอบเดี่ยว (เดิมเป็น Toggle framed) — เช่น "พักการใช้งาน" (checkbox ซ้าย):

<label className={`flex items-center gap-2 h-9 px-3 rounded-lg border
                    cursor-pointer select-none ${form.is_disabled
                      ? 'bg-destructive-soft border-destructive/30 text-destructive'
                      : 'bg-card border-border'}`}>
  <Checkbox checked={!!form.is_disabled}
            onCheckedChange={v => setF('is_disabled', v ? 1 : 0)} />
  <span className="text-sm">พักการใช้งาน</span>
</label>
ตัวเลือกลดความซ้ำ (เสนอ): สร้าง helper CheckRow ใน src/components/ui/ ที่ prop เหมือน Toggle เป๊ะ (checked / onChange / label / framed / variant) แต่ render Checkbox แทน Switch (วาง checkbox ซ้าย / label ขวา) → จุดที่ใช้ label เดี่ยว (LabelFormDialog, People, CustomerFormDialog ฯลฯ) แปลงแบบเปลี่ยนชื่อ <Toggle>→<CheckRow> 1:1; ส่วนแถว title+subtitle (EditProduct/UnitsTab/QuickStock) ใช้ <Checkbox> ดิบใน label ตามโค้ดบน เพราะ layout 2 บรรทัดต่างจาก helper

หมายเหตุก่อนลงมือ

Checkbox primitive มีอยู่แล้ว — src/components/ui/checkbox.tsx (Radix) ใช้งานจริงอยู่แล้วใน column-visibility popover (ProductsList/BundlesList), DrugTypesTab, LabelPrintDialog ฯลฯ → แปลงได้เลย ไม่ต้องสร้างใหม่
มติ: LabelSettingsTab:621 — เปลี่ยนเป็น checkbox ให้เหมือนทั้งหน้า และ เอา disclosure ออก: เดิมซ่อนช่องความสูง/กว้าง/ตำแหน่งเมื่อปิด → เปลี่ยนเป็นแสดงเสมอ แต่ disabled ช่องเหล่านั้นเมื่อ show_barcode ไม่ได้ติ๊ก
Disclosure toggles ที่กลายเป็น checkbox — has_tax_invoice, is_alert เปิดแล้วเผยช่องย่อยทันที (UX ทันที) แต่ "ค่าที่เซฟ" ยังต้องรอปุ่มบันทึก จึงจัดเป็น checkbox ตามเกณฑ์ — การเผยช่องเป็นแค่ผลข้างเคียงของ UI ไม่ใช่การ persist  ·  ส่วน is_drug เจ้าของขอคงเป็น Switch
ไม่ต้องแตะ — showcase ใน Theme/index.tsx (เดโม primitive Switch/Toggle) คงไว้เป็นเอกสารของ primitive; ตัว switch.tsx เองก็ไม่แตะ (ทั้ง Switch และ Toggle wrapper)
ความสอดคล้อง state shape — Switch ปัจจุบันใช้ onCheckedChange (Switch) / onChange (Toggle wrapper, ส่ง boolean), ส่วน Checkbox primitive ใช้ onCheckedChange(v) โดย v เป็น boolean | "indeterminate" → ตอนแปลงต้องเช็ค v === true หรือ v ? 1 : 0 ให้ตรง pattern เดิม (ดู ProductsList.tsx:224 เป็นตัวอย่าง)
