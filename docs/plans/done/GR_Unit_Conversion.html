แปลงหน่วยตอนรับสินค้า (GR) เป็นหน่วยฐาน

หน้าบ้านยังรับเข้าเป็นโหล/กล่องได้ แต่หลังบ้านแตกเป็นหน่วยฐานก่อนเก็บสต็อก/ต้นทุน/FEFO — โดยคงหน่วยที่รับจริงไว้ในประวัติ

ผ่าน audit 2 รอบ ขอบเขต: GR save · cancel · ประวัติ · ข.ย.9 · wizard 2026-06-20

1 ภาพรวม — ทำอะไร ทำไม

ปัญหาวันนี้: ตอนรับสินค้า ระบบเก็บจำนวนและต้นทุนที่กรอก ดิบ ๆ ตามหน่วยที่เลือก (กล่อง/โหล) ลง product_lots โดย ไม่แปลงเป็นหน่วยฐานเลย — payload ก็ไม่ได้ส่งหน่วยที่เลือกขึ้น backend ด้วยซ้ำ ผลคือถ้ารับ "1 โหล" (12 ชิ้น) สต็อกขึ้นแค่ 1 ทั้งที่ POS อ่าน qty_on_hand เป็นหน่วยฐาน → สต็อก/ต้นทุนเฉลี่ย/FEFO เพี้ยน

แผนนี้แก้: ให้ หน้าบ้านรับเข้าเป็นหน่วยอะไรก็ได้เหมือนเดิม แต่ตอนบันทึก backend จะแตกเป็นหน่วยฐานก่อนเก็บ (qtyBase = qty × qty_per_base, costBase = cost ÷ qty_per_base) ส่วน ประวัติการรับ/ใบรับ/ข.ย.9 ยังโชว์หน่วยที่รับจริง (เช่น "2 โหล @ 120") เพื่อความตรงกับบิลผู้ขาย

หัวใจ: ยอดเงินรวม (จำนวน × ต้นทุน) ไม่เปลี่ยน ไม่ว่าจะคิดเป็นโหลหรือชิ้น → รายงานการเงินทุกตัวไม่กระทบ

2 โครงสร้าง / แผนผัง

เส้นทางบันทึก GR — จุดแปลงหน่วยอยู่ที่ backend จุดเดียว แล้วแยกออกเป็น 2 ทาง: ประวัติเก็บ "ค่าที่กรอก" (โหล) ส่วนสต็อก/ต้นทุนเก็บ "หน่วยฐาน" (ชิ้น)

ผู้บริโภคปลายทาง: ประวัติ/ใบรับ + ข.ย.9 อ่านจากกล่องบน (โหล) · POS · FEFO · ต้นทุนเฉลี่ย · ข.ย.10/11 อ่านจากกล่องล่าง (ชิ้น)

3 ก่อน ↔ หลัง (ตัวอย่าง: รับ 2 โหล, 1 โหล = 12 ชิ้น, @ 120 บาท/โหล)

ก่อน

  • product_lots.qty_on_hand = 2 ผิด (ควร 24)
  • product_lots.cost_price = 120 ผิด (ควร 10)
  • POS เห็นสต็อกแค่ 2 ชิ้น · ต้นทุนเฉลี่ย/FEFO เพี้ยน
  • ประวัติไม่บอกหน่วย — qty 2, cost 120 อ่านกำกวม
  • payload ไม่ส่งหน่วยที่เลือกขึ้น backend

หลัง

  • qty_on_hand = 24 · cost_price = 10 ถูก
  • POS/FEFO/ต้นทุนเฉลี่ย ใช้หน่วยฐานครบ
  • ประวัติ/ใบรับ/ข.ย.9 โชว์ "2 โหล @ 120"
  • ยอดรวม ฿240 เท่าเดิม — รายงานการเงินไม่ขยับ
  • ยกเลิก GR คืนสต็อก −24 (ไม่ใช่ −2)

4 ส่งผลอย่างไร

ข้อดี

  • สต็อก/ต้นทุน/FEFO ถูกต้องเมื่อรับเป็นหน่วยใหญ่ — ฟีเจอร์เลือกหน่วยรับเข้าใช้ได้จริงเสียที
  • ประวัติยังตรงกับบิลผู้ขาย (document fidelity) ตามกฎต้นทุนเดิม
  • ยอดเงินรวมไม่เปลี่ยน → ไม่ต้องแตะรายงานการเงิน/แดชบอร์ด
  • ฟรีพ่วง: แก้บั๊กเดิมที่ตอนยกเลิก GR เคย log unit_cost เป็นราคารวม VAT

ข้อเสีย / ต้นทุน

  • เพิ่ม 2 คอลัมน์ใน purchase_receipt_items + ต้องประกาศ schema 3 จุด
  • แตะหลายไฟล์ (save · cancel · getReceipt · reports · wizard) — ต้อง click-test ครบ

ข้อควรระวัง

  • กฎ blank→0: ตอน re-default ต้นทุนใน selectUnit ห้ามใช้ ?? 0 — ของฟรี/ไม่เคยซื้อต้องคงช่องว่าง
  • is_closed toggle: ทั้ง 4 จุดที่ผูก item.qty ใน UPDATE ตอน merge ต้องเป็น qtyBase พร้อมกัน
  • ยกเลิก GR: ต้องแปลง line.qty × qty_per_base เป็นหน่วยฐานก่อนคืนสต็อก ไม่งั้นคืนผิด
  • ข้อมูลเก่า: แถวก่อนมีคอลัมน์ใหม่ได้ qty_per_base=1/unit_name=NULL → COALESCE fallback เป็นหน่วยฐาน (ตั้งใจ ใช้กับของใหม่เท่านั้น)
  • document fidelity: purchase_receipt_items.cost_price ยังเก็บราคาที่กรอก (รวม VAT สำหรับบิล inclusive) ห้ามแปลงเป็น ex-VAT/หน่วยฐาน

5 UX / UI

  • หน้ารับสินค้า (Wizard): ไม่มีปุ่ม/หน้าจอใหม่ — แค่ช่อง "ต้นทุน/หน่วย" ในขั้นที่ 2 จะเติมค่าตั้งต้นเป็น ต่อหน่วยที่เลือก (เช่น เลือกโหล → เติม ทุนล่าสุด × 12). กล่องอ้างอิง "ทุนล่าสุด" (สีอำพัน amber-soft/amber-strong) ที่ปรับไปก่อนหน้านี้จะกลายเป็นถูกต้องจริง
  • ประวัติการรับ / ใบรับ (PurchaseReceiptDialog, Manage/Purchases): คอลัมน์หน่วยจะโชว์หน่วยที่รับจริง (โหล) แทนหน่วยฐาน — ตัวเลขเงินเท่าเดิม
  • ข.ย.9: คอลัมน์หน่วยตามหน่วยที่รับจริง; ข.ย.10/11 (ทะเบียนขาย) ยังเป็นหน่วยฐานตามเดิม
  • ไม่มี string/ปุ่มใหม่ที่ต้องใช้ token เพิ่ม — ไม่กระทบ /theme

B แผนปฏิบัติงาน (Claude อ่านส่วนนี้แล้วลงมือ)

Goal

Receiving can use any unit (กล่อง/โหล) on the front-end, but stock & cost are stored in the BASE unit on the backend, while the originally-entered receiving unit is kept in the ledger (document fidelity). Conversion is applied SERVER-SIDE (single point): qtyBase = qty × qty_per_base; costBase = (cost × VAT costFactor) ÷ qty_per_base. Money total (qty × cost) is invariant.

Definition of done

  • Receive 2 โหล (qty_per_base=12) @ 120/โหล, NO-VAT → product_lots: qty_received=qty_on_hand=24, cost_price=10; purchase_receipt_items: qty=2, cost_price=120, unit_name='โหล', qty_per_base=12; POS base stock +24; weighted-avg correct.
  • ประวัติการรับ + ใบรับ show "2 โหล @ 120".
  • ข.ย.9 shows "2 โหล"; ข.ย.10/11 (sale ledger) shows lot qty_received in BASE (24 ชิ้น) — intended.
  • Cancel restores qty_on_hand by −24 (not −2); blocker compares base qty; cancel stock_movements.unit_cost = base ex-VAT (matching receive — also corrects the pre-existing incl-VAT bug).
  • Old GRs (qty_per_base default 1, unit_name NULL) behave exactly as before everywhere (COALESCE fallback).
  • npx tsc --noEmit clean except the pre-existing src/pages/Theme/index.tsx warning-outline error.
