VAT was reworked because the old free on/off toggle let an operator disable VAT per bill — auditable gap in the RC- sequence (สรรพากร red flag). One codebase; VAT mode changes only through **guarded, audited flows** (upgrade = wizard/upgradeToVat; downgrade = admin password re-entry + reason), never a toggle. Per-product VAT-exempt NOT built (all goods taxable); off-the-books mode was refused.

**STATUS 2026-06-10 — full VAT structure BUILT in one pass (tsc PASS; in-app click-test NOT done yet):**

- **Phase 1 (setup wizard) — DONE 2026-05-31.** `settings:completeSetup` writes shop + VAT atomically.
- **Phase 2 (hide VAT UI when NO-VAT) — DONE 2026-06-10.** New hook `src/hooks/useShopVat.ts` (UI-gating only — stored bills always read their own snapshot). Gated: tax-invoice menu in `SaleDetailDialog` + `Manage/Sales` kebab, abbrev-tax-invoice toggle in `ReceiptSettingsTab`. POS/slip were already data-gated (`vatEnabled` / `total_vat > 0`).
- **Phase 3 (lock toggle + upgrade flow) — DONE 2026-06-10.** `settings:saveSalesSettings` now **strips `vat_enabled`/`vat_rate` main-side** (can't be flipped even by crafted payload). `settings:upgradeToVat` (requireAdmin): validates 13-digit tax id + rate + effective date, writes settings + sales_settings + a row in new table **`vat_audit_log`** in one tx; throws if already VAT. UI: `Settings/SalesTab` VAT card = read-only status (Badge จด/ไม่จด + rate + วันที่จด) + "เปิดใช้ระบบ VAT" button → `UpgradeVatDialog` (`src/components/dialogs/UpgradeVatDialog.tsx`, prefills from getShop).
- **Guarded downgrade — DONE 2026-06-10 (operator request, replaced "no downgrade by design").** `settings:downgradeFromVat({password, reason})`: requireAdmin + re-verify the **logged-in admin's own password** (verifySecret + login lockout backoff → throws 'LOCKED' with remainingMs) + mandatory reason; tx = `vat_enabled=0` + `vat_audit_log` row (`action='downgrade'`, new `reason` column). Registration data KEPT in settings (re-upgrade prefills); old bills' VAT snapshots untouched. UI: SalesTab VAT card row "เพิกถอนทะเบียน VAT แล้ว?" + destructive2 button → `DowngradeVatDialog` (red impact box, reason Textarea, password field; footer destructive primary + destructive2 cancel). **Reports ภาษี tab = `vatEnabled || hasVatHistory`** (operator chose ข้อ ก: past periods stay inspectable; `settings:hasVatHistory` = EXISTS vat bills/GR vat/audit rows). After downgrade all other VAT UI hides automatically via useShopVat.
- **Purchase-side input VAT (ภาษีซื้อ) — DONE 2026-06-10.** `purchase_receipts` + 3 cols: **`vat_mode` ('none'|'inclusive'|'exclusive') per bill** (operator decision 2026-06-10: ต้องเลือกได้ต่อบิล เพราะบางแหล่งซื้อไม่มี VAT), `vat_rate`, `vat_amount` (computed main-side in `purchase:save`; base = line sum — renderer already distributes bill discount/surcharge into lines). **Cost model rule:** ledger `purchase_receipt_items.cost_price` keeps the entered invoice price (document fidelity); the cost model (`product_lots.cost_price`, weighted avg, `last_cost_price`, `stock_movements.unit_cost`) stores **ex-VAT** cost (`costEx = entered × 100/(100+rate)` for inclusive bills) because claimable VAT is not cost. NO-VAT shop forced `vat_mode='none'` main-side (its VAT paid IS cost). UI: Purchase sidebar "ภาษีซื้อ (VAT)" card (only when shop VAT) + footer VAT preview; `PurchaseReceiptDialog` tfoot refactored to dynamic summary-row array (sticky bottom offsets via literal-class lookup) + VAT row; `purchase:getReceipt` returns vat cols. `PURCHASE_NET_SUB` in reports.ts now adds vat_amount for 'exclusive' bills (payable/purchase totals = money actually owed).
- **Expense input VAT — DONE 2026-06-10.** `expenses` + `vat_amount` + `has_tax_invoice` (claimable only with full tax invoice; vat forced 0 main-side when unchecked, validated vat < amount). `ExpenseFormDialog`: toggle "มีใบกำกับภาษีเต็มรูป" + VAT field (prefill = extractVat(amount)), only when shop VAT.
- **VAT reports — DONE 2026-06-10.** `reports:vatSummary` (admin) → output (sales.total_vat, voided excluded) / input (GR vat + expense vat) / `net_vat` (ภ.พ.30). Page `src/pages/Reports/VatReport.tsx` at `/reports/vat`: 3 MetricCards + 3 tables (ภาษีขายรายบิล / ภาษีซื้อ GR / ภาษีซื้อค่าใช้จ่าย), MultiDatePicker month-default. Tab "ภาษี (VAT)" in Reports — **hidden for NO-VAT shops** (route stays registered).
- **Setup wizard VAT path — UNBLOCKED 2026-06-10.** validateStep2 early-return removed; tax-id/branch/rate/date fields restored in step 2.
- **Per-bill sale VAT checkbox — DONE 2026-06-10 (operator request, same day).** POS payment dialog, left column above the print toggle, VAT shops only: "คิดภาษีมูลค่าเพิ่ม (VAT x%)" checkbox. Operator-confirmed semantics: **ถอดจากราคาเดิม** (inclusive — customer pays the same; tick = VAT backed out + recorded, untick = total_vat 0, bill out of ภาษีขาย report) and **default = CHECKED, re-armed on every payment-dialog open** (no memory of last choice). Implementation: `vatApplied = vatEnabled && vatChecked` feeds pendingVat + receipt preview + saveBill — all three must share the flag. Tax-invoice action now also gated `total_vat > 0` (SaleDetailDialog + Manage/Sales) so a NOVAT bill can't issue a tax invoice. ⚠️ Note: this deliberately reintroduces per-bill VAT discretion that Phase 3 removed at the *settings* level — surfaced to operator (NOVAT bills don't enter ภาษีขาย/ภ.พ.30) and accepted; bills still record in the system either way.

**Key facts:**
- VAT snapshotted per-sale (`sales.total_vat`/`sale_items.unit_vat` at sale time; reprints read stored values via normalizeSale.ts) — enabling VAT never re-VATs old bills.
- Prices are VAT-inclusive; `extractVat` in `src/lib/vat.ts` backs tax out.
