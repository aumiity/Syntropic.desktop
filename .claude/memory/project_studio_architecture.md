Syntropic.Studio (AI-agent dashboard, plan at `docs/plans/syntropic-studio.md`) — locked cross-platform decisions so the operator can switch between MacBook / PC (`ZEMA-PC`) / Mac mini freely, with everything following git.

**Memory location = Option A (in-repo).** Project & convention memory lives in `.claude/memory/` in the repo and is loaded into every session via `@.claude/memory/MEMORY.md` in CLAUDE.md — works in normal `claude` AND Studio, on every machine, because it rides on git-tracked CLAUDE.md. **Write project/convention memory to the repo dir, NOT the per-machine OS auto-memory dir** (`~/.claude/projects/.../memory/`). Only personal cross-project prefs ([[feedback-thai-language]], [[feedback-address-as-sister]]) stay in OS/global. Migrated 16 existing memories from OS → repo on 2026-06-01.

**Engine = headless stream-json, NOT node-pty.** Studio server spawns `claude -p --output-format stream-json --input-format stream-json --verbose` via `child_process.spawn` — structured events on stdout, input (permission replies) via stdin. No JSONL tailing (the OS transcript path is mangled per-machine), no pty/conpty. Cross-OS for free.

**Agents must be path-free.** Sub-agents run with the parent session's cwd, so agent prompts use relative paths and `npx tsc --noEmit` — never hardcode `/Users/anya/...` or `D:\...`, never `cd`. This is why hunter runs bare `npx tsc --noEmit`.

**Machine root = auto-detect, never prompt.** `server/machines.json` (git-tracked) maps `os.hostname()` → repo root. Resolve silently; only ask when an unknown hostname appears (new machine), then persist + push. `ZEMA-PC` = current PC.

**Why:** operator moves machines often and prompts from iPhone; the original plan hardcoded macOS paths and a node-pty + JSONL-watcher design that only worked on one machine.

**Terminal entry to the crew = the `claude-studio` shell alias (2026-06-11).** Type `claude-studio` in a terminal (in any project's dir) → launches `claude --plugin-dir <studio>/office`, loading the crew into that session. The alias lives in `~/.zshrc` (per-machine, NOT git-tracked): `alias claude-studio='claude --plugin-dir /Users/CYUT/Documents/GitHub/Syntropic.studio/office'` — set it once per machine with that machine's path (PowerShell: a `function` in `$PROFILE`). Inside, run `/claude-studio <quest>` to drive the pipeline. The `/claude-studio` command is the orchestrator added at `office/commands/claude-studio.md` (git-tracked, travels): reads the target repo's CLAUDE.md, classifies trivial→assassin vs normal→wizard→blacksmith→priest→hunter→kafra with the priest NEEDS-FIX loop. Setup/usage doc = `installation.md` at the Studio repo root. **Do NOT use the global `claude plugin install` route** — it double-loads with the alias's `--plugin-dir` (and with Studio's own server spawn) and risks duplicate `office:*` agents; the alias is the single mechanism. Plugin name stays `office` (do NOT rename — engine.ts strips the `office:` subagent prefix). Studio's web-cockpit server path is unaffected — it loads the same `office/` via `--plugin-dir` independently.

**Resume trap (2026-07-05).** `--plugin-dir` is a per-launch flag — it is NOT persisted (`enabledPlugins` in `~/.claude.json` stays empty for inline plugins). So resuming a conversation with plain `claude --resume <id>` loads the session WITHOUT the `office` crew → `office:*` subagents vanish and the running Claude misreports them as "disabled/ถูกปิดไป" (it never got loaded). The `claude-studio` PowerShell function (in `$PROFILE`, WinPS 5.1) is present and correct on ZEMA-PC — the failure is invoking `claude` directly instead of through it. To resume WITH the crew: `claude-studio -- --resume <id>` (the `--` forwards the rest straight to claude → `claude --plugin-dir …office --resume <id>`). Same trap for any fresh launch not via `claude-studio`.

**Status 2026-06-02:** Phase 0 (6 agent files + dispatch section) committed to Syntropic.desktop. Phase 1 (server + web dashboard) lives in sibling repo `D:/Syntropic.Project/Syntropic.studio` (separate git history, root commit `bca5c62`), pushed to **private** `github.com/aumiity/Syntropic.studio`. To run on Mac/Mac mini: clone, `npm install` (clean, no native — uses `node:sqlite`), add that machine's `os.hostname()` to `server/machines.json` (server throws an actionable error until you do), `npm run dev`. Engine verified end-to-end on ZEMA-PC; NOT yet exercised against a real dispatching pipeline run, and WS-to-browser only checked via REST polling. Two cross-platform gotchas found + fixed (worth remembering): (1) on Windows `spawn('claude', [...], {shell:true})` splits an argv prompt containing spaces/`?` — deliver the prompt on **stdin** instead; (2) Tailwind `content` globs are relative to cwd not the config file, and Vite's `root: web/` breaks them — use **absolute** content paths. `claude -p` event facts: `system/init` carries `session_id`+`agents`; sub-agent dispatch = `tool_use` name `Task` with `input.subagent_type`; child lines carry `parent_tool_use_id`; fresh spawns pay ~38k cache-creation tokens each (~$0.05 floor).
